Electronic signatures (`SIGNED`) and protocol or hypothesis approvals lock your record permanently (<a href={`${import.meta.env.BASE_URL}/ch14-completeness-audit-and-signatures#signing-an-item-and-verifying-signature-integrity`}>Chapter 14: Signing an item and verifying signature integrity</a>). Run through these ten checks before you click **Sign** or ask your supervisor to review your experiment.

## 1. Every action has its raw files attached

Expand your **Procedure** row in the **Items** panel with **Expand all below** (<a href={`${import.meta.env.BASE_URL}/ch3-a-tour-of-the-main-window#reading-the-item-tree-and-its-row-buttons`}>Chapter 3: Reading the item tree and its row buttons</a>). Every **Procedure** and **Action** in the tree should have its native instrument or analysis files attached beneath it, and no placeholder action should sit empty. For a deposition run using `.depo.json`, verify that its paired `.tsv` log file is attached to the same item so time-series charts work.

## 2. Every file opens in its built-in viewer

Click through the attached files in the **Items** panel and check the **Content Viewer** on the right (<a href={`${import.meta.env.BASE_URL}/ch7-raw-files-drafts-and-instrument-viewers#inside-the-five-core-instrument-viewers`}>Chapter 7: Inside the five core instrument viewers</a>). Confirm that `.depo.json` opens in the **Deposition** viewer (not plain JSON), `.fibps` shows its height map, `.mit` plots the load-displacement curves, `.zrw` plots the friction curve, and `.xrcx` shows both the reflectivity curves and the **Structure** table. If you edited any attachment in an external program or the **Markdown Editor**, make sure you saved your working draft (**Tools > Save Attachment Working Draft**).

## 3. Shared regions and intervals are applied

In the **FIBPS** viewer, check that the step-height rectangles **A** and **B** sit on flat, clean areas of the coated and uncoated levels (or that the automatic **Wear Track** groove boundaries bracket the wear scar cleanly). In the **MIT** viewer, check that unphysical indents are unticked in **Records:**. In the **ZRW** viewer, check that the plateau cycle interval is set and that you clicked **Apply** so the shared selection is saved with the file (<a href={`${import.meta.env.BASE_URL}/ch7-raw-files-drafts-and-instrument-viewers#table-7-1`}>Chapter 7: Table 7-1</a>).

## 4. Headline values carry Reader or Derived sources

Open each **Procedure** and **Action** with **Item > Edit** and inspect its **Values** tab (<a href={`${import.meta.env.BASE_URL}/ch9-values-units-formulas-and-provenance#the-four-value-sources-and-derived-formulas`}>Chapter 9: The four value sources and Derived formulas</a>). Every measurement that has a file reader should show a `Reader` source naming the reader ID, version, key, and file, and every formula output (such as reciprocating wear rate $K$) should show a `Derived` source naming the formula ID, version, and input values. If a value shows `Manual`, verify that it is a quantity with no file reader and that its **Description** explains how it was measured.

## 5. Repeated measurements show mean and SD

When an action holds multiple measurements of the same quantity (such as the three step-height scans `1.fibps`–`3.fibps` or the three wear-track scans `wear 1.fibps`–`wear 3.fibps` in Study A), check the summary on the item tree row. Because all three values share the same Value Type, Record Type (`Result`), and Description, the tree row should display their mean, sample standard deviation, and count: for example, `d = 343.0 ± 23.5 nm (n=3)` (<a href={`${import.meta.env.BASE_URL}/ch3-a-tour-of-the-main-window#reading-the-item-tree-and-its-row-buttons`}>Chapter 3</a>). If `(n=6)` appears when you attached only 3 files, check for duplicate manual entries.

## 6. Sample codes match across items and files

Check that the sample code in the **Specimen** title (such as `261015A` or `261014B`) matches the code in the parent **Procedure** title, every child **Action** title, and the attached filenames (<a href={`${import.meta.env.BASE_URL}/ch4-your-first-complete-sample-record#table-4-1`}>Chapter 4: Table 4-1</a>). Consistent sample codes allow **Navigate > Search...** (`Ctrl+F`) and `eln://specimen/<CODE>` links to locate every record of that specimen without ambiguity.

## 7. Required protocol forms are completed

If your procedure or action uses a structured **Protocol** (<a href={`${import.meta.env.BASE_URL}/ch8-filling-out-protocols-and-checklists#adding-and-completing-a-protocol-on-an-item`}>Chapter 8: Adding and completing a protocol on an item</a>), click the protocol row and read its rendered HTML in the **Content Viewer**. If the template uses `AutoFill` fields such as `values.all`, make sure the protocol was created *after* you extracted the item's values so the summary snapshot is populated, and move **Validation Status** from `Draft` to `In Review` when ready.

## 8. Data Completeness reports zero missing items

Select your project or folder and run **Tools > Data Completeness...** (or right-click the project and choose **Data Quality Check...** in the team client; <a href={`${import.meta.env.BASE_URL}/ch14-completeness-audit-and-signatures#completeness-rules-and-data-quality-checks`}>Chapter 14: Completeness rules and Data Quality Checks</a>). Confirm that no action fails a required file-type or value-type rule, and run `report_value_issues` via MCP (<a href={`${import.meta.env.BASE_URL}/ch16-reading-data-and-auditing-drift-via-mcp#running-the-three-project-wide-health-checks`}>Chapter 16</a>) to confirm zero out-of-range values or tolerance-scale mismatches.

## 9. Check Value Sources reports zero drift

Right-click the root **Procedure** of your experiment and choose **Check Value Sources...** (or run `check_value_drift` and `check_storage` via MCP; <a href={`${import.meta.env.BASE_URL}/ch9-values-units-formulas-and-provenance#checking-value-sources-and-understanding-drift-codes`}>Chapter 9: Checking value sources and understanding drift codes</a>). Confirm that every attachment's MD5 checksum is `ok` and that every `Reader` and `Derived` value reports `unchanged` with zero `value_changed`, `selection_changed`, or `input_changed` warnings.

## 10. Hypothesis runs and citations are current

If your experiment tests a hypothesis (<a href={`${import.meta.env.BASE_URL}/ch10-the-hypothesis-tree-and-evidence#attaching-runs-and-citing-evidence`}>Chapter 10: Attaching Runs and citing Evidence</a>), open **Project > Hypotheses**, select the hypothesis, and check its **Runs** and **Evidence** tabs. Confirm that the procedure or specimen is attached as a `Run`, that the final files and values are cited on the **Evidence** tab, and that no cited row shows a `changed` or `missing` warning before you click **Submit conclusion**.
