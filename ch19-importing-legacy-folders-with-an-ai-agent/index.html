Part 4 · Chapter 19

Importing Legacy Folders with an AI Agent

In This Chapter

  • Turning an instrument-first or date-first folder archive into a specimen tree
  • Having an agent scan folders, deduplicate files by MD5, and draft a migration plan
  • Separating Reader values extracted from raw files and Manual conditions from Word or Excel logs
  • Walking through a real migration from D:\ResearchProjects\TiNiZr\ into APS ELN

In Chapter 17 and Chapter 18, your AI agent recorded new samples (261014B and 261015A) right after the measurements finished. Every laboratory also has years of older work sitting on shared drives or external disks, such as D:\ResearchProjects\. Those folders were created before the laboratory used APS ELN. An AI agent connected through MCP (Chapter 15) can migrate a legacy folder into a structured, provenance-verified ELN project in minutes. To keep the import clean, follow a four-phase workflow that puts a human review gate before any database write (Figure 19-1).

Why legacy folders break direct import

APS ELN organizes every record around the physical sample: a Procedure produces a Specimen, each measurement is a child Action, the native raw file sits on that action, and Values point back to the file (Chapter 1: The four links in every laboratory result). Legacy drives like D:\ResearchProjects\ grew in the opposite direction:

  1. Instrument-first folders: A project folder such as D:\ResearchProjects\TiNiZr\ splits measurements of the same specimen across separate subfolders. It puts nanoindentation in UNHT\, 3D laser profilometry in Wear\, tribometry in COF\, scanning electron microscopy in SEM\, and transmission electron microscopy in TEM #1\ through TEM#3\. Broader archive trees like D:\ResearchProjects\_Experiments\ put ten years of unrelated samples under UNHT\, LAXRD\, 3DProfiler\, Sputtering\, and Tribotest\.
  2. Date-first folders: Inside _Experiments\UNHT\2016-07-18\ or TriboTester Development\2026-04-30\, folders are named after the calendar date of the instrument session rather than the specimen code.
  3. Conditions hidden inside collaborator documents: Deposition and annealing conditions sit in Word documents (Specimens_List_2_(10-15).docx, C60+Nitrogen\specimens.docx) or Excel workbooks (Deposition log (Co-C) 2015-12-18.xlsx). Collaborators often wrote these notes in Russian or Ukrainian using free-form tables and paragraphs.
  4. Duplicates, print exports, and cross-sample compilations: Byte-identical copies appear under slightly different names (TiNiZr_9B#1.mit and TiNiZr_09B#1.mit, both 11.3 MB11.3\,\text{MB}11.3MB) or inside backup subfolders (Set 1\UNHT\). In Wear\, native Keyence confocal height maps (12-5N-5k.vk4) sit next to exported print reports (12-5N-5k.rpt) and counterbody ball scans (Ball-12-5N-5k.vk4). At the folder root, OriginLab projects (ALL_COF.opj, H&WR_vs_Temp.opju) and slide decks (compilation.pptx) combine 20 specimens in a single file.

If you tell an agent to “import everything in D:\ResearchProjects\TiNiZr\”, it will create duplicate specimens for 9B and 09B. It will also attach 20-sample .opju plots to a single specimen and guess which load belongs to 12-3.vk4. Instead, use the mapping rules in Table 19-1 across four distinct phases.

Phases 1 and 2: Reconnaissance and the migration plan

The first two phases are 100% read-only. The agent inspects the legacy folder on disk without modifying a single file in D:\ResearchProjects\ and without calling any MCP write tool.

  1. Phase 1: Read-only inventory and MD5 deduplication. Point your agent (DSH or OMP) at the legacy project folder, such as D:\ResearchProjects\TiNiZr\. Ask it to list all subfolders, compute MD5 hashes for every file, and read any .docx, .xlsx, .md, or .txt specimen lists. In TiNiZr\, the MD5 pass catches that UNHT\TiNiZr_9B#1.mit and UNHT\TiNiZr_09B#1.mit are byte-for-byte identical. It also shows that Set 1\UNHT\ and Set 1\Wear\ are earlier folder copies of files already sitting in UNHT\ and Wear\.
  2. Phase 2: The human-approved Migration Plan. Ask the agent to match the specimen numbers in the .docx lists against the filenames in UNHT\, Wear\, COF\, SEM\, and TEM #1\–TEM#3\. Have it output a structured Migration Plan table before touching APS ELN.

The Migration Plan table must separate confident matches from questions for you. For example, in D:\ResearchProjects\TiNiZr\Wear\, sample #12 has 12-1.vk4, 12-3.vk4, 12-3N-5k.vk4, 12-5N-1k.vk4, 12-5N-5k.vk4, Ball-12-3N-5k.vk4, and Ball-12-5N-5k.vk4. An agent can read the load (3 N3\,\text{N}3N vs. 5 N5\,\text{N}5N) and cycle count (100010001000 vs. 500050005000 cycles) from 12-3N-5k.vk4 and 12-5N-5k.vk4. However, it must ask you whether Ball-12-5N-5k.vk4 (the counterbody ball scar) belongs on the same wear action as 12-5N-5k.vk4. It must also ask which test conditions correspond to 12-1.vk4 and 12-3.vk4:

You: Scan D:\ResearchProjects\TiNiZr\ in read-only mode. Read Specimens_List_2_(10-15).docx, match samples #10 through #15 to their raw files in UNHT\, Wear\, and COF\, check for duplicate files by MD5, and show me a Migration Plan table before calling any ELN write tools.

Assistant: Scanned D:\ResearchProjects\TiNiZr\ (read-only) and read Specimens_List_2_(10-15).docx.

  • Batch context (Specimens_List_2_(10-15).docx): Single-layer magnetron-sputtered TiNiZr\text{TiNiZr}TiNiZr coatings, nominal thickness 2.5 μm2.5\,\mu\text{m}2.5μm, deposited under identical conditions. Samples #13 (unannealed) and #14 (600 ∘C600\,^\circ\text{C}600∘C) sit on Al2O3\text{Al}_2\text{O}_3Al2​O3​ substrates (∅15×1 mm\varnothing 15 \times 1\,\text{mm}∅15×1mm). Samples #10 (500 ∘C500\,^\circ\text{C}500∘C), #11 (550 ∘C550\,^\circ\text{C}550∘C), #12 (750 ∘C750\,^\circ\text{C}750∘C, over-annealed Laves phase + Zr\text{Zr}Zr solid solution), and #15 (200 ∘C200\,^\circ\text{C}200∘C, amorphous check) sit on Cr18Ni10Ti\text{Cr18Ni10Ti}Cr18Ni10Ti (Х18Н10Т) stainless steel (2.25 mm2.25\,\text{mm}2.25mm thick).
  • Duplicates and exports to skip: Set 1\UNHT\ and Set 1\Wear\ duplicate the root UNHT\ and Wear\ folders by MD5. In Wear\, 12-3N-5k.rpt, 12-5N-5k.rpt, and 15-1.rpt are exported print reports that sit beside native .vk4 maps (12-3N-5k.vk4, 12-5N-5k.vk4).
  • Questions before I stage or upload anything:
    1. For sample #12, should Ball-12-3N-5k.vk4 and Ball-12-5N-5k.vk4 be attached to the same Wear track actions as 12-3N-5k.vk4 and 12-5N-5k.vk4?
    2. Sample #15 has 15-2.vk4 in Wear\ and 15-1.rpt (with no 15-1.vk4). Should I attach 15-2.vk4 alone or also keep 15-1.rpt for completeness?

Warning: Never let an agent write to ELN before you approve the migration plan

Calling create_item and upload_file on a legacy folder before reviewing the mapping table creates orphan specimens, duplicate Reader values, and misfiled scans. Always require a read-only Migration Plan table first and answer the agent’s questions before Phase 3 begins.

Phase 3 follows three strict rules so the original archive stays untouched and every stored value carries honest provenance:

  1. Stage approved files into --upload-root without modifying D:\ResearchProjects\. As covered in Chapter 15: Security, upload-root, and review boundaries, upload_file only reads paths inside your configured --upload-root directory. Never point --upload-root at the entire D:\ drive or rename files inside D:\ResearchProjects\. Instead, have the agent copy only the approved, deduplicated files into a clean staging subfolder inside --upload-root (for example C:\ELN-Upload\TiNiZr-Batch2\).
  2. Attach the collaborator .docx or .xlsx log to the parent Procedure and record its conditions as Manual. The agent creates project TiNiZr, folder Batch 2 (Samples 10-15), and procedure Deposition TiNiZr Batch 2 (Proc). It uploads Specimens_List_2_(10-15).docx to Deposition TiNiZr Batch 2 (file_id = 1). Next, it records the nominal coating thickness (2.5×10−6 m2.5 \times 10^{-6}\,\text{m}2.5×10−6m) on Deposition TiNiZr Batch 2 and the annealing temperature (500 ∘C500\,^\circ\text{C}500∘C, 550 ∘C550\,^\circ\text{C}550∘C, 750 ∘C750\,^\circ\text{C}750∘C, 600 ∘C600\,^\circ\text{C}600∘C, or 200 ∘C200\,^\circ\text{C}200∘C) on each specimen’s Annealing action. It calls add_value with source_kind: "Manual" and a Description that names the attached Word document: "From attached Specimens_List_2_(10-15).docx (file_id = 1)".
  3. Extract raw instrument measurements through the Value Route (Reader provenance). For TiNiZr_10#1.mit, TiNiZr_11#1.mit, TiNiZr_12#1.mit, and TiNiZr_15#1.mit, the agent uploads each .mit file to its Indentation action. It then runs extract_file_key_values (aps.mit) and passes the returned Reader provenance fields verbatim to add_values (Chapter 17: Why agent-written records need the Value Route).

Remember

Never let an agent disguise a number read from a .docx, .xlsx, or .pdf prose table as a Reader value. Reader provenance is reserved for numbers extracted by a registered viewer plugin via extract_file_key_values. Historical conditions transcribed from legacy documents must be stored as Manual values whose Description cites the attached document.

Tip

Many collaborator documents in D:\ResearchProjects\ are written in Russian or Ukrainian (Specimens_List_2_(10-15).docx, C60+Nitrogen\Описание_образцов50819.docx, Old Data (Jeju)\таблица.docx). Always attach the original .docx file unchanged, and ask the agent to include an English summary in the Procedure or Specimen description so both languages are searchable.

Phase 4: Linking an Experiment Series, filing compilations, and auditing

Once the individual specimen trees are built (Deposition TiNiZr-10 through Deposition TiNiZr-15), you can connect the whole batch into an Experiment Series (Chapter 13: Planning and running an Experiment Series) so APS ELN compares and plots the annealing sweep natively:

  1. Ask your agent to call create_series (Chapter 18) on the TiNiZr project with factor Temperature (label: "Annealing", levels 200, 500, 550, 600, 750), fixed condition Thickness (2.5×10−6 m2.5 \times 10^{-6}\,\text{m}2.5×10−6m), and responses Hardness and Modulus.
  2. In the Desktop GUI, open Project > Series…, review the Draft series, and click Start to make it Active.
  3. In the center Items panel, select the imported top-level procedures, right-click, and choose Link to plan point…. APS ELN matches each procedure to its temperature point and populates the series Table and Plot tabs automatically.

Next, handle the cross-sample analysis files sitting at the root of D:\ResearchProjects\TiNiZr\: H&WR_vs_Temp.opju, WR.opju, Nanoindentation.opj, ALL_COF.opj, Wear_Rate.mcdx, compilation.pptx, and Thermal_Conductivity_#2.pdf. Each of these files compares many specimens across annealing temperatures.

Do not attach a multi-specimen .opju or .pptx file under one arbitrary specimen. Instead, ask your agent to call wiki_create_page (Chapter 18: Drafting and updating Wiki pages) to create a page under the Analysis section of the Project Wiki (for example, title: "Legacy TiNiZr Compilations and Summary Plots"):

  • In body_md, the agent writes a table linking every imported specimen ([[specimen:TiNiZr-10]] through [[specimen:TiNiZr-15]]; Chapter 11) and explains what each legacy compilation file contains.
  • In attachments, the agent passes the staged paths of H&WR_vs_Temp.opju, WR.opju, compilation.pptx, and Thermal_Conductivity_#2.pdf. In APS ELN, .opju files display their embedded OriginLab graph previews directly in the OPJU viewer, while .docx, .pptx, and .pdf attachments are indexed for Search by meaning (search_semantic in Chapter 12 and Chapter 16).
Going Deeper: Legacy .opj files versus modern .opju files
OriginLab switched from the older binary .opj format (ALL_COF.opj, Nanoindentation.opj) to the Unicode .opju format (H&WR_vs_Temp.opju, WR.opju) in Origin 2018. APS ELN’s built-in OPJU viewer plugin renders embedded graph thumbnails from .opju files directly in the Content Viewer. Older .opj files are still stored with full MD5 integrity and can be opened in Origin via working drafts (Chapter 7), or re-saved as .opju if you want inline graph previews.

Finally, have the agent run the three project-wide MCP audit calls from Chapter 16: Running the three project-wide health checks on the newly imported TiNiZr project:

  1. check_storage (project_id): confirms that every staged .docx, .mit, .vk4, .opju, and .pptx file sits in ELN attachment storage with an MD5 hash matching upload time (missing: 0, content_mismatch: 0).
  2. check_value_drift (project_id): re-runs aps.mit on every imported .mit file and confirms drifted_count: 0 across all extracted Reader values (while reporting the documented .docx annealing temperatures under skipped_manual_or_unknown).
  3. report_value_issues (project_id): checks that every converted unit (such as 2.5×10−6 m2.5 \times 10^{-6}\,\text{m}2.5×10−6m for the 2.5 μm2.5\,\mu\text{m}2.5μm coating thickness) and every tolerance sits inside its value type’s plausible range (issue_count: 0).

In a Team Lab

When migrating a shared legacy archive into a team laboratory server via ELNMCPServer.exe, create the project first and use Share… in the Desktop client (Chapter 5: Sharing projects in a team laboratory). That way, the collaborators who made the original samples can inspect the imported tree and verify the viewer selections.
