Part 1 · Chapter 2

Opening a Local or Team Lab Notebook

In This Chapter

  • Understanding how local Community notebooks and shared Team servers store data
  • Creating, opening, and switching local SQLite notebooks in APS ELN Community
  • Logging into a shared laboratory server and using Demo Mode in a team lab
  • Backing up your database and attachment directory together without losing files

Before you can create a project or record a sample (Chapter 1: The four links in every laboratory result), you need an open notebook. You can open a local notebook on your PC in APS ELN Community or sign into a shared server in APS ELN (“For Teams”). Once the notebook is open, the scientific workspace is the same (Chapter 3: The three-panel workspace).

Two ways ELN stores your laboratory work

APS ELN keeps two things in sync (Figure 2-1):

  1. The database: projects, folders, procedures, specimens, actions, values, protocols, hypotheses, experiment series, tags, links, signatures, and the audit log.
  2. The attachment store: the raw measurement files, note images, and analysis projects you attach.

In APS ELN Community, both parts sit in normal folders on your Windows PC: one SQLite database file (such as notebook.sqlite) and one separate attachment directory (such as notebook files). There is no server login.

In APS ELN (“For Teams”), the structured records are stored on a shared MySQL server and the attachment bytes are stored on a shared WebDAV or server store. You log in with the username and password issued by your laboratory administrator.

Creating a local notebook in Community

When you launch ELNCommunity.exe for the first time, no notebook is open yet. Follow these steps to create your first notebook:

  1. Choose File > New Notebook….
  2. In the file dialog, pick a folder on a local drive and type a new database file name, such as notebook.sqlite. Do not select an existing file.
  3. Select a separate, empty attachment directory. By default, the dialog creates and opens a new empty <name> files folder right beside your .sqlite file; click Select Folder to accept it. The .sqlite file itself must sit outside the attachment folder.
  4. Enter your First name, Last name, Signing password, and password confirmation in the local-profile dialog, then complete the dialog.
  5. Wait a moment while APS ELN checks the seven scientific reference catalogs (ValueTypes.csv, FileTypes.csv, ActionTypes.csv, EquipmentTypes.csv, Equipment.csv, ActionTypeEquipment.csv, FileTypeLinks.csv) and imports the reference data into your new notebook.

In ELN

Use File > New Notebook… to create a new .sqlite notebook, File > Open Notebook… to open an existing one, and File > Recent Notebooks to switch among the last eight notebooks you opened.

If you accidentally choose an existing file in File > New Notebook…, Community stops with a warning before asking for an attachment folder and leaves the existing file untouched. Use File > Open Notebook… instead.

When you open an existing notebook with File > Open Notebook…, Community checks whether the database already remembers its attachment directory:

  • On the same drive, the notebook stores the attachment folder as a relative path (for example, ..\Files when agent.sqlite sits in a DB folder beside Files). If the folder is present, the notebook opens immediately.
  • If the notebook has no saved attachment path, or if the folder moved separately, Community asks you to select that notebook’s attachment folder. It then asks whether to remember the path for next time.

Warning: your signing password is not a file-encryption password

The signing password you set when creating a local notebook is checked only when you apply an electronic signature to lock a record (Chapter 14: Signing an item and verifying signature integrity). Opening a local .sqlite notebook does not ask for a password, and the database is not encrypted. Protect your computer account and backup drives with Windows access controls.
Going Deeper: opening older format 2, 3, 4, or 5 notebooks and command-line flags

Current Community builds use local notebook format 6, which includes schema tables for Derived values, experiment series (Project > Series…), default reader mappings, and the tribology value types (Wear area, Normal force, Cycles, and Wear rate). When you open an older format 2, 3, 4, or 5 notebook, Community asks before changing anything. Clicking Yes writes a timestamped backup copy beside your database (named with .format2-backup-, .format3-backup-, .format4-backup-, or .format5-backup-). It then upgrades the database to format 6 and preserves all existing values and sources. Older versions of Community cannot open a format 6 database, so keep that backup file if you ever need an older build.

You can also launch Community from a script or shortcut with explicit paths:

ELNCommunity.exe --config "C:\ELN\desktop.ini" --notebook "C:\ELN\notebook.sqlite" --storage "C:\ELN\notebook files" --plugins "C:\ELN\Plugins"

When you launch Community without command-line flags, it automatically reopens the last notebook that opened cleanly.

Logging into a shared team server

In a research group that runs the Commercial team edition (ELabNotebook3.exe), your notebooks sit on the laboratory server. Your teammates and supervisor can then view shared projects, review protocols, and approve hypotheses.

In a Team Lab: first-run connection and server login

  1. First-run setup: The first time you start ELabNotebook3.exe on a workstation, the First-Run Connection Wizard asks how to connect. In a managed lab, select the .elnconfig configuration file provided by your administrator; it fills in the MySQL database and WebDAV attachment server automatically.
  2. Logging in: On the Login screen, enter your Username and case-sensitive Password, then click Log in. A Caps Lock warning appears automatically if Caps Lock is on. Click the eye icon beside the password box to check what you typed, and tick Remember credentials to store your login in Windows Credential Manager.
  3. Three-strike lockout: After three failed login attempts in a row, the program closes. Relaunch it to try again, or ask your administrator to reset a forgotten password.

In a team laboratory, your account carries one of five roles (Table 2-1). Most students work with a Standard or PowerUser account.

Table 2-1: User roles in a shared Team laboratory notebook.

RoleWhat a user with this role can do
GuestRead projects granted to them; cannot create or edit scientific records or see review queues.
StandardCreate and edit procedures, specimens, actions, files, protocols, and values in projects where they have write access; submit protocols and hypotheses for review.
PowerUserEverything a Standard user can do, plus create new projects of their own and manage reference data where permitted.
Super (Supervisor)Review and approve student protocols and hypotheses across supervised projects, and filter the Dashboard by student and time range.
AdminManage user accounts, roles, permissions, audit rules, and server configuration.

Tip

To practice creating items or testing value extraction without touching your group’s live server database, use Demo Mode on the login screen. You can also open the Study A and Study B local .sqlite demonstration notebooks in APS ELN Community.

How to back up a local notebook safely

In APS ELN Community, changes save to the .sqlite file as soon as you close a dialog. There is no File > Save Notebook command. When you back up your work, remember that the .sqlite file alone is only half of your notebook. The database stores file names and MD5 hashes, while the actual curves and images sit in the attachment folder.

Follow these five steps whenever you back up or move a local notebook:

  1. Save open editors. Save any open Markdown note or external working draft (Tools > Save Attachment Working Draft), and resolve any conflict prompts.
  2. Close the notebook and stop MCP processes. Close ELNCommunity.exe and verify that no ELNCommunityMCP.exe agent process is using the database. Never copy a SQLite database while a program is writing to it.
  3. Copy the database and attachment folder together. Copy both the .sqlite file and the entire <name> files folder into one backup folder or archive. Keep the subfolder structure and filenames unchanged.
  4. Copy retained working drafts if needed. If you declined to save a working draft at close and kept its temporary recovery path, copy that draft folder separately.
  5. Test your backup in a new folder. When restoring, extract both the .sqlite file and the attachment folder into a new directory. Do not overwrite an existing notebook in place. Then open it with File > Open Notebook… and check a few files in the viewer.

Remember

To move a closed Community notebook to another folder or drive, move the parent folder that holds both the .sqlite database and its attachment folder. Because the notebook saves a relative path on the same drive, it will find its attachments at the new location automatically.

Warning: never delete SQLite sidecar files by hand

If a notebook was not closed cleanly, you may see -journal, -wal, or -shm files next to the .sqlite database. Never delete those files in Windows Explorer to clear a lock warning; they hold uncommitted database pages. Open and close the database in its owning client so SQLite can recover them cleanly.
