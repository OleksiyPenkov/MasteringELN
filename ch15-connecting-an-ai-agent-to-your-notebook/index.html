Part 4 · Chapter 15

Connecting an AI Agent to Your Notebook

In This Chapter

  • Understanding how the ELN Model Context Protocol (MCP) server works
  • Launching ELNCommunityMCP.exe with --notebook, --upload-root, and --plugins
  • Registering ELNMCPServer.exe with DSH or OMP in a team laboratory
  • Knowing the security, upload-root, and human-review boundaries enforced by the server

Instead of clicking through menus for every repetitive check, you can connect an AI assistant such as DeepSeek Harness (DSH) or OMP to APS ELN through the Model Context Protocol (MCP) server. The assistant can search across projects, inspect time-series logs, and audit every stored value against its raw file in seconds. It can also fit an X-ray reflectivity curve (Chapter 17) and build structured experiment trees (Chapter 18), all under the server’s built-in safety boundaries (Figure 15-1).

What the ELN MCP server does

Both editions of APS ELN include a command-line MCP host executable installed right beside the Desktop program (Figure 15-1):

  • ELNCommunityMCP.exe (APS ELN Community): opens a local format 5 .sqlite notebook and its attachment folder on your computer.
  • ELNMCPServer.exe (APS ELN “For Teams”): connects to your shared laboratory MySQL and WebDAV server using your workstation’s configuration.

When an AI client starts the MCP host, they communicate over standard input and standard output (stdio) using one UTF-8 JSON-RPC 2.0 message per line. The MCP host loads the same scientific domain model and the same 26 .bpl viewer plugins as the Desktop GUI. Calling extract_file_key_values from an agent therefore runs the exact same reader code (aps.deposition, aps.fibps, aps.mit, aps.zrw, aps.xrcx) as clicking Extract Values on screen (Chapter 9: Reader mappings, unit factors, and standard deviations).

Preparing a local session in APS ELN Community

In APS ELN Community, the installer uses a per-user folder (%LocalAppData%\Programs\ELN Community, which expands to C:\Users\<you>\AppData\Local\Programs\ELN Community) rather than C:\Program Files, so you can install and update it on a student or university PC without Windows Administrator privileges. It places ELNCommunityMCP.exe in that folder right next to ELNCommunity.exe. Follow these steps to prepare a local MCP session safely:

  1. Create your notebook in the Desktop program first, then close the Desktop. A local Community notebook uses a single-user SQLite file. Close ELNCommunity.exe before starting an MCP session that writes to that same .sqlite file.
  2. Create a dedicated upload/staging folder (--upload-root). Create an ordinary local folder (such as C:\ELN\Inbox) with no directory junctions or symbolic links. Place only the raw measurement files you want the agent to upload (or the files exported by download_file) inside this folder.
  3. Configure your MCP client with absolute paths:
ELNCommunityMCP.exe --notebook "C:\ELN\notebook.sqlite" --upload-root "C:\ELN\Inbox" --plugins "C:\Users\<you>\AppData\Local\Programs\ELN Community\Plugins"

If your .sqlite notebook already remembers its attachment folder (Chapter 2: Creating a local notebook in Community), ELNCommunityMCP.exe uses that saved folder automatically. If not, pass --storage "C:\ELN\notebook files" as well.

Warning: never pass --config to ELNCommunityMCP.exe

--config is a Desktop-only flag (ELNCommunity.exe). ELNCommunityMCP.exe takes --notebook, --upload-root, --plugins, and optional --storage, and it only opens an existing format 5 notebook; it never creates or migrates a database.

Registering with DSH or OMP in a team laboratory

In a team laboratory running the Commercial edition, the installer places ELNMCPServer.exe in C:\Program Files\E-LabNotebook3\.

In a Team Lab: registering ELNMCPServer.exe with DSH or OMP and clicking eln:// links

ELNMCPServer.exe reads your server connection settings, credentials, WebDAV URL, and upload root directly from the Windows Registry configured by the Desktop client. You can register it in either OMP or DeepSeek Harness (DSH).

In OMP (~/.omp/agent/mcp.json): add the eln entry under "mcpServers":

{
  "mcpServers": {
    "eln": {
      "type": "stdio",
      "command": "C:\\Program Files\\E-LabNotebook3\\ELNMCPServer.exe",
      "enabled": true
    }
  }
}

In DeepSeek Harness ($DSH_HOME/profiles/web/cordis.patch.yml): add the eln server to the mcp-manager configuration:

- id: mcp-manager
  config:
    servers:
      eln:
        transport: stdio
        command: 'C:\Program Files\E-LabNotebook3\ELNMCPServer.exe'
        enabled: true

(If you upgraded from an older 32-bit build in C:\Program Files (x86)\E-LabNotebook3\, update the command path to C:\Program Files\E-LabNotebook3\ELNMCPServer.exe.)

Every MCP tool that returns an item (list_items, get_item, create_item, update_item) includes a clickable url field such as eln://item/42. Because the Desktop client registers the eln:// protocol handler in Windows on startup, clicking eln://item/42 in a Markdown-rendering chat window focuses the Desktop application and jumps straight to item 42.

Tip

In the Commercial Desktop client, right-click any project, folder, or item in the tree and choose Copy MCP Link. Paste that reference directly into your chat prompt so your AI assistant knows the exact project or item ID without searching.

Security, upload-root, and review boundaries

An AI agent can make fast, persistent changes to a notebook, so the ELN MCP server enforces five hard boundaries inside its own code (Figure 15-1):

  1. Project and account scope: Every tool call reloads the active user principal and checks project permissions. Attempting to read or write an item or file in a project you cannot access returns the same out of scope error as a non-existent ID. An agent cannot probe private projects.
  2. Upload-root file confinement (--upload-root / MCPUploadRoot): Both upload_file (reading a local file into ELN) and download_file (copying an attached file out of ELN) are strictly confined to --upload-root. The server refuses any path outside that folder, any .. traversal, any Windows device prefix (\\?\, \\.\), any alternate data stream, or any directory junction/symlink along the path. Never set --upload-root to C:\ or your entire user profile.
  3. Signed-item and cited-item locks: The MCP server refuses to edit, add values to, replace files on, or delete any item carrying an electronic signature (SIGNED, Chapter 14). It also refuses to delete files or values cited by a hypothesis in InReview or Accepted (Chapter 10).
  4. Read-only session mode: A read-only MCP session hides all write tools from tools/list and refuses any call that modifies data (Tool "name" is not available in a read-only session.). All read and audit tools (list_projects, get_item, get_values, search, check_value_drift, check_storage) remain available.
  5. No MCP tools for human review gates: Calling approve_hypothesis or accept_conclusion returns tool-not-found. Approving protocols (Chapter 8), approving or accepting hypotheses (Chapter 10), and signing items (Chapter 14) can only be performed by a human in the GUI.
Going Deeper: line-based JSON-RPC stdio initialization

When an MCP client launches ELNCommunityMCP.exe or ELNMCPServer.exe, it sends an initialize request line, followed by notifications/initialized. It then calls tools/list to read the JSON Schema of every registered tool before making any tools/call request:

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_projects","arguments":{}}}

Diagnostic messages from viewer packages go to stderr so stdout carries pure JSON-RPC lines, and closing stdin terminates the server cleanly.
