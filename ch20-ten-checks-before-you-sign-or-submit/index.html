Part 5 · Chapter 20

Ten Checks Before You Sign or Submit

In This Chapter

  • Ten checks to run before signing an item or submitting to your supervisor
  • Verifying files, viewer intervals, provenance badges, and drift
  • Ensuring a colleague can trace every number back to its raw file

Electronic signatures (SIGNED) and protocol or hypothesis approvals lock your record permanently (Chapter 14: Signing an item and verifying signature integrity). Complete these ten checks before you click Sign or ask your supervisor to review your experiment.

1. Every action has its raw files attached

Expand your Procedure row in the Items panel with Expand all below (Chapter 3: Reading the item tree and its row buttons). Every Procedure and Action in the tree should have its native instrument or analysis files attached beneath it, and no placeholder action should sit empty. For a deposition run using .depo.json, verify that its paired .tsv log file is attached to the same item so time-series charts work.

2. Every file opens in its built-in viewer

Click through the attached files in the Items panel and check the Content Viewer on the right (Chapter 7: Inside the five core instrument viewers). Confirm that .depo.json opens in the Deposition viewer (rather than plain JSON), .fibps shows its height map, and .mit plots the load-displacement curves. Also check that .zrw plots the friction curve and .xrcx shows both the reflectivity curves and the Structure table. If you edited any attachment in an external program or the Markdown Editor, verify that you saved your working draft (Tools > Save Attachment Working Draft).

3. Shared regions and intervals are applied

In the FIBPS viewer, check that the step-height rectangles A and B sit on flat, clean areas of the coated and uncoated levels. For wear scans, check that the automatic Wear Track groove boundaries bracket the wear scar cleanly. In the MIT viewer, check that unphysical indents are unticked in Records:. In the ZRW viewer, check that the plateau cycle interval is set and that you clicked Apply so the shared selection is saved with the file (Chapter 7: Table 7-1).

4. Headline values carry Reader or Derived sources

Open each Procedure and Action with Item > Edit and inspect its Values tab (Chapter 9: The four value sources and Derived formulas). Every measurement that has a file reader should show a Reader source naming the reader ID, version, key, and file. Every formula output (such as reciprocating wear rate KKK) should show a Derived source naming the formula ID, version, and input values. If a value shows Manual, verify that it is a quantity with no file reader and that its Description explains how it was measured.

5. Repeated measurements show mean and SD

An action often holds multiple measurements of the same quantity, such as the three step-height scans 1.fibps–3.fibps or the three wear-track scans wear 1.fibps–wear 3.fibps in Study A. Check the summary on the item tree row. Because all three values share the same Value Type, Record Type (Result), and Description, the tree row displays their mean, sample standard deviation, and count: for example, d = 343.0 ± 23.5 nm (n=3) (Chapter 3). If (n=6) appears when you attached only 3 files, check for duplicate manual entries.

6. Sample codes match across items and files

Check that the sample code in the Specimen title (such as 261015A or 261014B) matches the code in the parent Procedure title. It should also match every child Action title and the attached filenames (Chapter 4: Table 4-1). Consistent sample codes allow Navigate > Search… (Ctrl+F) and eln://specimen/<CODE> links to locate every record of that specimen without ambiguity.

7. Required protocol forms are completed

If your procedure or action uses a structured Protocol (Chapter 8: Adding and completing a protocol on an item), click the protocol row and read its rendered HTML in the Content Viewer. If the template uses AutoFill fields such as values.all, verify that the protocol was created after you extracted the item’s values so the summary snapshot is populated. Then move Validation Status from Draft to In Review when ready.

8. Data Completeness reports zero missing items

Select your project or folder and run Tools > Data Completeness… (or right-click the project and choose Data Quality Check… in the team client; Chapter 14: Completeness rules and Data Quality Checks). Confirm that no action fails a required file-type or value-type rule, and run report_value_issues via MCP (Chapter 16) to confirm zero out-of-range values or tolerance-scale mismatches.

9. Check Value Sources reports zero drift

Right-click the root Procedure of your experiment and choose Check Value Sources… (or run check_value_drift and check_storage via MCP; Chapter 9: Checking value sources and understanding drift codes). Confirm that every attachment’s MD5 checksum is ok and that every Reader and Derived value reports unchanged with zero value_changed, selection_changed, or input_changed warnings.

10. Hypothesis runs and citations are current

If your experiment tests a hypothesis (Chapter 10: Attaching Runs and citing Evidence), open Project > Hypotheses, select the hypothesis, and check its Runs and Evidence tabs. Confirm that the procedure or specimen is attached as a Run and that the final files and values are cited on the Evidence tab. Verify that no cited row shows a changed or missing warning before you click Submit conclusion.
