Part 4 · Chapter 16

Reading Data and Auditing Drift via MCP

In This Chapter

  • Browsing projects, items, and values with structured MCP read tools
  • Running hybrid Semantic Search (searchsemantic) with numeric value filters
  • Inspecting long time-series logs with listfilecolumns and getfilecolumns
  • Auditing an entire project with checkstorage, checkvaluedrift, and reportvalueissues

The safest way to start using an AI assistant with APS ELN (Chapter 15: What the ELN MCP server does) is through its read-only tools. In one prompt, your assistant can list all specimens in a folder, filter semantic search hits by numeric value ranges, summarize a 10,000-row sputtering log, and check every file hash and value across a project (Figure 16-1).

Navigating and querying values

When you ask an AI assistant a question about your notebook, it uses seven structured read tools to navigate the hierarchy and inspect values (Table 16-1):

  • list_projects and list_folders: return your readable projects (with item counts, owner, and dates) and the folder tree (folder_id and parent references) inside a project.
  • list_items and get_item: list_items filters a project by folder_id, item_type (Synthesis, Specimen, Measurement, Testing), or level (Proc, Item, Action). get_item returns one item’s full details: its children, attached files (with file_id, extension, and MD5 hash), recorded values, note/protocol entries, and tags.
  • get_values and query_values: get_values returns all values on one item grouped into experimental conditions (EXP_CONDITION) and test results (TEST_RESULT). It also includes ancestor_ids (from the root procedure down to the direct parent) and each value’s source object (Reader, Derived, Manual, or Unknown). query_values searches values across a project by value_type (title or symbol), rec_type, and item creation date (date_from, date_to).
  • correlate_values: pairs condition values and result values across items in a project (the MCP counterpart of Tools > Analysis… in Chapter 13: Plotting conditions against results).

Searching by text and meaning (search and search_semantic)

The MCP server exposes both search engines from Chapter 12: Three ways to find a record in APS ELN:

  • search: runs full-text search across items, protocols, files, values, and tags (with optional project_id). Every file match returns its file_id, full_name (preserving compound extensions such as .depo.json and .process.log), and extension.
  • search_semantic: runs hybrid semantic search (query, optional top_k from 1 to 50, and optional project_id) over record fields and attachment text (PDF, Office, Markdown, HTML, JSON, XML, CSV, RTF, and text). When the cross-encoder reranker is installed, it re-sorts the top 20 item groups (reranked: true).

Unlike the Desktop Search dialog (which offers only project, item type, and creation date filters), search_semantic in MCP also accepts structured numeric value filters before ranking:

  • folder_id, item_types, levels, and action_type_id: restrict the search to a specific folder subtree, item types (such as ["Measurement", "Testing"]), levels (["Proc", "Item", "Action"]), or action type.
  • date_field, date_from, and date_to: filter by created (default) or modified ISO 8601 dates.
  • values: an array of numeric range filters, where each entry specifies value_type (symbol or title), rec_type (EXP_CONDITION or TEST_RESULT), min, max, and requested_unit. For example, you can find all coatings related to low friction in humid air whose Hardness is between 5 and 10 GPa. The server converts min and max into the stored unit of the value type and echoes the converted limits in filters_applied.

Remember

If search_semantic is called on a large notebook while the indexer is still reading newly attached PDFs, the response includes "index": {"complete": false, "pending_passages": ..., "files_pending": ...}. Call search_semantic again after a moment to let the background index catch up.

Reading tabular instrument logs (list_file_columns and get_file_columns)

Sputtering logs (.tsv, .log) and tribometer curves often contain tens of thousands of time-series rows. Dumping an entire 8 MB .tsv file into an AI prompt would overflow the model’s context window. Instead, APS ELN provides a two-step columnar tool pair:

  1. Discover the columns (list_file_columns): Pass file_id. The server uses the file’s viewer plugin to return total_rows, time_span, and the list of columns (index, name, units, and dtype).
  2. Fetch summary statistics or downsampled series (get_file_columns): Pass file_id, the columns you want (by index or column name), and one of three modes:
    • mode: "stats": returns the count, minimum, maximum, mean, and standard deviation of each requested column.
    • mode: "downsample" (the default): bins the series into max_rows (default 500) min/max buckets so the agent sees every spike and drop in at most 1,000 points.
    • mode: "raw": returns unbinned rows, optionally sliced to row_range: [start, end].

Tip

Always ask your agent to call list_file_columns and get_file_columns with mode: "stats" or "downsample" first. Request mode: "raw" over a narrow row_range only when inspecting a specific event such as an arc or pressure spike.

Running the three project-wide health checks

To check an entire project or item subtree in one pass, have your assistant run these three read-only tools (Figure 16-1 and Table 16-1):

  1. check_storage: give project_id, item_id (which checks the item and all of its descendants), or file_ids. The server checks that every attachment’s physical file exists in storage and compares its MD5 hash against the hash recorded at upload time. It returns counts of ok, missing, content_mismatch, no_hash, and error.
  2. check_value_drift: give project_id or item_id. The server re-runs the current reader plugin on the source file of every Reader value (replaying any saved .fibps pixel regions or .zrw cycle interval from analysis_snapshot). It also recalculates every Derived value recursively from its inputs (Chapter 9: Table 9-1). In Study A (261015A), it returns {"checked": 24, "unchanged": 24, "drifted": []}; in Study B (261014B), it returns {"checked": 22, "unchanged": 22, "drifted": []}.
  3. report_value_issues: give project_id or item_id. Scans all stored values against their value type’s plausible range and tolerance factor (1000×1000\times1000×), flagging below_range, above_range, tolerance_exceeds_value, and tolerance_scale_mismatch.

Table 16-1: Read-only MCP inspection and audit tools.

MCP toolKey argumentsWhat it returns
get_item / get_valuesitem_idItem metadata, children, files, and values with ancestor_ids and full source provenance.
search_semanticquery, project_id, folder_id, item_types, valuesHybrid semantic + keyword matches across records and document text, with pre-filters and top-20 reranked order.
list_file_columns / get_file_columnsfile_id, columns, mode (stats, downsample, raw)Column metadata and summary stats or min/max-binned series from tabular logs (.tsv, .log, .dat).
check_storageproject_id, item_id, or file_idsMD5 and presence check for stored attachments (ok, missing, content_mismatch, no_hash, error).
check_value_driftproject_id or item_idRe-runs readers and Derived formulas; returns checked, unchanged, and any drifted rows with status codes.
report_value_issuesproject_id or item_idLists stored values failing below_range, above_range, tolerance_exceeds_value, or tolerance_scale_mismatch.

Warning: scope check_value_drift and check_storage to item_id in legacy projects

If you add a new sample to an older project that contains historical records from before file hashes or reader tracking were enforced, project_id checks will include those old items. Pass item_id (your new root Procedure or Action) to verify your new subtree cleanly.
