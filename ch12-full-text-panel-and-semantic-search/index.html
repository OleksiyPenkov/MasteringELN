Part 3 · Chapter 12

Full-Text, Panel, and Semantic Search

In This Chapter

  • Filtering the Projects and Items panels in real time without losing context
  • Finding exact words and phrases across a notebook with Navigate > Search
  • Setting up and running Semantic Search (Search by meaning) across PDFs and notes
  • Using Rerank results, Project/Type/Created filters, and Go to Item

Once your notebook has dozens of depositions, hundreds of files, and multi-page Wiki notes (Chapter 11: The five-section Project Wiki), clicking through folders one by one takes too long. Sometimes you know the exact sample code (261015A). Sometimes you remember a phrase from a value note (masked edge). Other times you want every record about delamination after reciprocating wear, even if the note called it spallation or coating peeling. APS ELN gives you three search tools for those three jobs (Figure 12-1).

Three ways to find a record in APS ELN

Each search tool in APS ELN covers a different scope (Figure 12-1 and Table 12-1):

  1. Panel filters: the filter boxes at the top of the Projects and Items panels narrow the visible tree in real time as you type.
  2. Notebook text search (Navigate > Search... in Community, or Edit > Search... in Team; Ctrl+F): searches record titles, descriptions, properties, entry titles, attachment titles, value descriptions, and tag names across every readable project.
  3. Semantic search (Search by meaning inside Search...): a hybrid search engine (ELN.Search) that runs offline on your PC in Community or on your lab’s search server in the Team edition. It indexes both structured records and the full text inside attached PDF, Office, Markdown, HTML, JSON, XML, CSV, RTF, and text files, matching by conceptual meaning as well as exact terms.

Filtering panels and jumping to a known ID

When you already have a project open and want to spot one sample or one file type quickly, use the filter box at the top of the panel:

  • Projects panel filter: matches project and folder titles and descriptions while keeping the parent hierarchy visible.
  • Items panel filter (Filter items...): matches item titles and descriptions, note/protocol entry titles, and attached file titles and descriptions inside the currently selected project or folder. Parent rows stay visible so a matching child action never loses its specimen context.

Remember

A panel filter hides non-matching rows temporarily; it never deletes anything. If a project or item seems to have disappeared, clear the text in the panel filter box first. Then click Show Archived in the Projects panel (Chapter 5: Archiving finished projects) and check Tools > Recycle Bin….

When a teammate, a Wiki page, or an audit report gives you an exact item number or internal URL, jump straight to it without searching:

  1. Choose Navigate > Go to Item… in Community, or View > Go to item… in the Team client (or press Ctrl+G).
  2. In Enter an item ID or eln:// URL:, type the positive integer item ID (such as 4) or paste an internal URL (such as eln://item/4 or eln://specimen/261015A).
  3. Click OK. APS ELN switches to the target project and selects the item in the tree.

Searching notebook text (Ctrl+F)

To search across all readable projects at once by word or phrase:

  1. Choose Navigate > Search… in Community, or Edit > Search… in the Team client (or press Ctrl+F).
  2. Type at least two characters into the search box and press Enter (or click Search). Clicking the drop-down arrow at the right end of the search box lets you repeat any of your last 20 searches.
  3. Inspect the result columns: ID (the owning item ID), Type (item, entry, file, value, or tag), Name, Location (project, folder, and parent item), and Matched In (which field matched). In the Team edition, an Owner column also appears to the left of ID so you can tell teammates’ projects apart.
  4. Click any result row (or move through the list with the Up and Down arrow keys). The main window behind the dialog navigates immediately to that item while keeping the Search window open so you can inspect several hits in a row. Press Esc to close the dialog.

How standard text search matches your query:

  • It first looks for your entire entered phrase as a case-insensitive substring.
  • If no record contains the exact multi-word phrase, it falls back to searching for the individual words (ignoring words shorter than two characters). It then returns items that contain all of those words across any of their fields.
  • Standard text search does not use wildcard symbols (*, ?) or Boolean operators (AND, OR). It also does not read inside attachment bytes, such as the body of a PDF or Markdown file. To search inside attachment contents or match synonyms, use Search by meaning.

Searching by meaning (Semantic Search) and reranking

Search by meaning uses a multilingual embedding model (E5) combined with lexical matching and an optional cross-encoder reranker. It searches both your structured notebook fields and the full text inside your attached documents.

In ELN

To enable semantic search for the first time in APS ELN Community, open a notebook and choose Tools > Semantic Search Setup…. Click Download and Install. APS ELN downloads the ONNX Runtime and embedding model first (~549 MB) and then the optional PDFium extractor and cross-encoder reranker (~117 MB, about 666 MB in total). After that one-time download, semantic search runs 100% offline on your computer; no notebook text is ever sent over the network.

In APS ELN Community, the semantic index is stored in a companion file next to your notebook with the extension .search.sqlite. Keep that file protected alongside your .sqlite database.

In a Team Lab: how Search by meaning works on a shared team server

In the Commercial (“For Teams”) edition, Search by meaning runs on your laboratory’s shared search server (ELN.WebAPI). That server indexes the MySQL database and WebDAV attachments centrally into notebook.search.sqlite. You do not download the ~666 MB model bundle on your own workstation, and there is no Semantic Search Setup… menu item.

Instead, an administrator (Admin or Super role) opens Tools > Settings…, switches to the Connection tab, and enters the Search server address (such as https://nas.lab:8443). After the next sign-in, your Desktop session authenticates to the search server automatically. The bottom of the Search window then shows the server’s live index status (Index complete: N passages · updated HH:MM), and every search is filtered to the projects you can read.

Once semantic search is available, open Search… (Ctrl+F) and tick Search by meaning:

  • What it reads: item titles, descriptions, and properties; tags; note and protocol entries; value descriptions; and attachment filenames. It also indexes the full text inside .pdf (up to 2,000 pages with PDFium), .docx, .pptx, .xlsx, .md, .html, .htm, .json, .xml, .csv, .rtf, and .txt files. Each file is indexed up to 64 MB and the first 200,000 characters.
  • Pre-ranking filters: when Search by meaning is ticked, three filters below the search box become active: Project, Type (item type), and Created (first and last UTC creation dates). Because these filters run before ranking, narrowing to one project or item type surfaces deep matches that might otherwise rank below top-20 hits from other projects.
  • Rerank results: when the optional reranking model is installed, the Rerank results check box is ticked by default (Figure 12-2). Hybrid search first retrieves the top 20 candidate items. The cross-encoder model then reads your query alongside each item’s best passage and full tree path to re-sort those 20 items in about 0.5 seconds. When the reranker order is shown, the result count above the list ends with reranked.

Tip

If you type a very short code or two-letter symbol (such as Co or BN) while Search by meaning is active, untick Rerank results or switch back to standard text search. Cross-encoder rerankers are trained on natural-language phrases and can rank a two-letter symbol lower than exact keyword search does.

Going Deeper: how the semantic index updates without slowing down your work

When you open a notebook or open the Search dialog, ELN.Search checks for new or modified items and attachments. It re-extracts text from an attached file only when the file’s byte size or last-write timestamp changes (and verifies the content hash if only the timestamp changed). Encrypted PDFs, legacy binary Office files (.doc, .xls, .ppt), image-only scanned PDFs without a text layer, and files over 64 MB are skipped cleanly without stopping index updates.
