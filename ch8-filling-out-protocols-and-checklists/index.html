Part 2 · Chapter 8

Filling Out Protocols and Checklists

In This Chapter

  • Attaching a structured protocol form to a procedure, specimen, or action
  • Using AutoFill fields (values.all, conditions.all, results.all) in protocol templates
  • Moving a protocol through Draft, In Review, Approved, and Rejected states
  • Submitting protocols from a phone at the instrument with the Quick Protocol web app

Raw files record what the instrument measured, and extracted Values (Chapter 9) store the numbers for plotting and search. Plenty of lab work, though, never shows up in a data file: how you cleaned and mounted the substrate, which target clamp you replaced, whether the cooling-water interlock passed, or why a coating looked hazy when you vented the chamber. Protocols record those checklists and setup notes right on the item.

Adding and completing a protocol on an item

A protocol is a structured form (or free-text entry) attached to a Procedure, Specimen, or Action (Chapter 6: Designing a clean item hierarchy). APS ELN ships with ready-to-use protocol templates across twelve categories in Assets/Runtime/ProtocolTemplates/. These include Deposition (CSMICSputtering.json, SputterIII_1Source.json–3Source.json), Characterization (XRD.json, XRF.json, SEM.json, TEM.json, AFM.json, 3DProfiling.json), and Testing (Indentation.json, TribotestProtocol.json, Adhesion.json), plus Sample Preparation, Safety, Quality, and Reporting (WeeklyLabReport.json).

Follow these steps to attach and complete a protocol:

  1. Select the parent Procedure, Specimen, or Action in the Items panel.
  2. Choose Item > Add Protocol (or press Ctrl+Shift+P in the team client).
  3. In the Select Template dialog, pick a category and a template (or choose (No template) for a free-text protocol), then click OK.
  4. In the Protocol Editor, check Title, Protocol Type (Experiment, Measurement, Analysis, Synthesis, Testing, Note, or Other), and Validation Status (Draft), and fill in the form fields.
  5. Click Save. When you select the protocol in the Items panel, the Content Viewer renders the completed form as formatted HTML.

Warning: switching templates clears your entered form fields

Inside the Protocol Editor, changing the Template drop-down clears all saved form fields on that protocol so the new schema can load. Never switch the Template drop-down to browse other templates after you have typed experimental notes into a form.

When you edit an existing protocol, an asterisk (*) marks unsaved changes. If you close the editor or click another item before saving, APS ELN prompts you to save, discard, or cancel so you never lose entries by accident.

How protocol templates and AutoFill work

You can inspect or customize protocol templates by choosing Reference Data > Protocol Templates… (or Templates > Protocol Templates… in the team client). Each template is built from sections (+Section), rows (+Row), and typed fields (+Field), and can be tagged with equipment types via Tags… (Table 8-1).

When a protocol is created on an item that already holds values or metadata, the template’s AutoFill bindings can pre-populate fields automatically (Table 8-1).

Table 8-1: Protocol field types and AutoFill value bindings.

Field type or AutoFill keyKindWhat it displays or inserts into the protocol
text, textarea, richtextField typeSingle-line text, multi-line text, or formatted rich-text blocks (use text or textarea for AutoFill summaries).
number, date, selectField typeNumeric entry, date picker, or drop-down list of predefined choices.
checkbox, checkbox-groupField typeSingle yes/no check box or multi-select checklist group.
values.allAutoFill sourceAll values on the item, grouping repeated values into mean ± SD (n=k), for example d = 343.0 ± 23.5 nm (n=3).
conditions.all, results.allAutoFill sourceEvery condition or every result on the item listed individually without grouping.
values.<Symbol>AutoFill sourceThe numeric value of the first stored value matching <Symbol> (such as values.H or results.COF).

Remember

Protocol form fields do not compute formulas or create Derived value provenance, and AutoFill inserts a one-time text snapshot when the protocol is created. Store quantitative results as item Values via Extract Values or Add > Derived Value… (Chapter 9: The four value sources and Derived formulas). Attach the protocol after those values are in place if your template uses values.all.
Going Deeper: protocol template versioning

When you edit and save a protocol template that is already used by existing records, APS ELN automatically creates a new template version instead of overwriting the old schema. Existing protocols keep the exact field layout they were completed with, while new protocols use the latest active version. Tick Show all versions (including inactive) in the Template Manager to inspect historical versions.

The protocol review workflow

Every protocol moves through four validation states (Figure 8-1):

  1. Draft: the author can edit all fields freely. When the form is complete, change Validation Status to In Review and click Save.
  2. In Review: the protocol is locked against ordinary edits and enters the review queue.
  3. Approved: the reviewer accepts the protocol. Once Approved, the protocol is permanently read-only and cannot return to Draft.
  4. Rejected: the reviewer rejects the protocol and enters a mandatory rejection reason. The author reads the reason, switches the protocol back to Draft, saves, fixes the issue, and submits it to In Review again.

In ELN

To process protocols waiting in In Review, choose Tools > Protocol Review… (Ctrl+Shift+R in the team client). Select a protocol to read its rendered preview, then click Approve or Reject. Inside any saved protocol’s editor, click History… to view the timestamped log of status changes, reviewers, and rejection comments.

In APS ELN Community, protocol review is a local self-check by the scientist on their own notebook. Like all human review gates in APS ELN, it must be performed in the Desktop GUI (the MCP server cannot approve or reject protocols).

Submitting protocols from the instrument in a team lab

In a team laboratory where instruments sit in a cleanroom or across the hall from your desk PC, you can complete a protocol right at the machine from your phone or tablet.

In a Team Lab: the Quick Protocol mobile web app

Laboratories running the Commercial ELN Web API server provide a mobile web app with three tabs (Quick Protocol, Waiting for me, and Projects). To record a run at an instrument in under a minute:

  1. Sign in on your phone with your lab username and password (you can register your phone as a trusted web device so future visits sign in automatically).
  2. Find the specimen by typing a few characters of its sample code (such as 261015A) into the autocomplete box.
  3. Pick a template: templates tagged for that instrument via Tags… and templates recently used on that specimen appear at the top of the list.
  4. Fill the fields, optionally snap a camera photo, and submit: the protocol and photo are written directly to the shared MySQL and WebDAV server under that specimen. They appear immediately in the desktop client’s Protocols Awaiting Review queue (Chapter 3: The Dashboard and keyboard navigation).
