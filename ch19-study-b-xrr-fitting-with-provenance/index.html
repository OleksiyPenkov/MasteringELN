Part 5 · Chapter 19

Study B: XRR Fitting with Provenance

In This Chapter

  • Understanding why agent-written records must store Reader values instead of prose numbers
  • Building the Study B (261014B Co/C mirror) tree and extracting 18 deposition values
  • Staging the .xrdml scan with downloadfile and fitting it in X-Ray Calc 3
  • Uploading the accepted .xrcx fit and storing its Reader values with zero drift

In Chapter 4, you recorded Study A (261015A) by hand in the Desktop window. Here, an AI agent records and fits Study B (261014B), a 20-period cobalt/carbon (Co/C\text{Co/C}Co/C) multilayer X-ray mirror on soda-lime glass. It uses ELNCommunityMCP.exe and the X-Ray Calc 3 MCP server (XRC_MCP.exe). Every raw file and call log for this walkthrough is in the book’s demonstration bundle (/MasteringELN/data/study-b/).

Why agent-written records need the Value Route

If you ask an AI agent to fit an X-ray reflectivity curve without strict rules, it usually does this:

  • It attaches the input files, runs the fit, and writes a Markdown note naming the source file, the job ID, and the fitted thicknesses.
  • It leaves 0 test result values on the action. Because the fitted period, layer thicknesses, and χ2\chi^2χ2 sit inside a text note instead of Reader-sourced Values, Tools > Analysis… (Chapter 15) and check_value_drift (Chapter 18) cannot plot or check any of them.

To prevent this, Study B enforces a strict Value Route: the agent is forbidden to type numbers by hand (Manual source) or leave results in prose only. Every stored number must come from calling extract_file_key_values on an attached file and passing the extracted fields verbatim to add_values with source_kind: "Reader" (Figure 19-1).

  2. Create the container and item tree: Calls create_project ("Study B: Co/C multilayer (demonstration)"), create_folder ("261014B"), and create_item four times to build:

    • Item 2 (Action, Treatment, parent 1): Cleaning 261014B
    • Item 3 (Item, Specimen, parent 1): 261014B (description: "Co/C multilayer, N = 20, on glass")
    • Item 4 (Action, Measurement, parent 3): XRR-1 261014B
  3. Upload the 7 raw files: Calls upload_file to attach the 3 deposition files to Item 1, the 3 plasma-cleaning files to Item 2, and XRR-1_Co-C(261014B).xrdml to Item 4.

Remember

Three domain facts in Study B show why you should always extract from .depo.json with is_key: true rather than guessing from logs. First, timeCo (42 s42\,\text{s}42s) and timeC (108 s108\,\text{s}108s) are sputtering times rather than layer thicknesses. Second, the Mean.* keys in .depo.json average over the entire run window including pump-down, so they are not deposition setpoints. Third, the .tsv units header labels current columns as A when the numbers are in mA. Attach the .tsv for time-series plots, and extract values only from .depo.json.

In a Team Lab: practicing Study B in your Practice group on the laboratory server

When you complete Study B for your laboratory practice assignment, first create the project Study B Practice inside your personal Practice group in the Desktop window (Project > New Group -> Practice, then right-click Practice -> New Project… -> Study B Practice). Unpack the 7 raw files from Study-B-261014B-raw.zip into your --upload-root folder. Next, instruct your AI agent (ELNMCPServer.exe and XRC_MCP.exe) to use your existing Study B Practice project and build folder 261014B and the four items of Part 1. Finally, have it fit XRR-1_Co-C(261014B).xrdml in XRC_MCP.exe (Part 2) and upload the accepted .xrcx file and its 4 Reader values under XRR fit 261014B.

Part 2: Fitting Agent records XRR fit 261014B

Once the raw scan XRR-1_Co-C(261014B).xrdml (file_id = 7) is in the notebook, you give the Fitting Agent (fitting_agent.md) this prompt to fit the curve and record the accepted fit back into APS ELN (Figure 19-1 and Table 19-1):

You: Fit the XRR curve on XRR-1 261014B (XRR-1_Co-C(261014B).xrdml, Co/C multilayer with N=20N = 20N=20 on soda-lime glass) using the xrr-fitting skill and csmic-empyrean preset. Once a candidate passes check_acceptance, save XRR-fit_Co-C(261014B).xrcx from curves.job_id (so [FITRESULT] and χ2\chi^2χ2 are stored), create child Computing action XRR fit 261014B under XRR-1 261014B, attach the .xrcx file, extract and store Period, Co Thickness, C Thickness, and Chi2 via the Value Route (source_kind: "Reader"), and run the storage, drift, and value-issue checks.

The Fitting Agent executes these six steps:

  1. Stage the .xrdml file out of ELN (download_file): When an attachment exists only inside ELN storage, an agent calls download_file with file_id and a dest_path inside the allowed --upload-root. The server verifies project read access, copies the bytes out, checks the MD5 hash against stored_hash, and returns storage_status: "ok" without altering notebook state.
  2. Assess and fit the curve in X-Ray Calc 3 (XRC_MCP.exe): Following the 13-step laboratory fitting procedure in the xrr-fitting skill (Mastering XRR Fitting), the agent calls assess_xrr. It then builds the starting model (SodaLimeGlass substrate / [C/Co]×20[\text{C} / \text{Co}] \times 20[C/Co]×20 / surface C\text{C}C contamination layer). It scans resolution (Δθ=0.014∘\Delta\theta = 0.014^\circΔθ=0.014∘) and runs 5-seed Periodic and Polynomial order 1 fits (fit_xrr, job_wait, job_result, verified by check_acceptance.py). Because the period drift across the 20 periods (ΔD=−0.336 A˚\Delta D = -0.336\,\AngΔD=−0.336A˚) exceeds twice the 5-seed spread (0.064 A˚0.064\,\Ang0.064A˚), the Polynomial order 1 fit (fit-20261016-153456-ea29, χ2=0.943\chi^2 = 0.943χ2=0.943) is accepted.
  3. Save .xrcx with curves.job_id so [FITRESULT] is written: The agent calls save_project passing curves.job_id = "fit-20261016-153456-ea29" and without a manual structure override, writing XRR-fit_Co-C(261014B).xrcx (MD5 106D0EFC42C3B0A200FFD9BE087BB1A5) with "fit_record": "FITRESULT".
  4. Create XRR fit 261014B and upload the .xrcx file: Back in ELNCommunityMCP.exe, the agent calls create_item to create child action XRR fit 261014B (Item 5, level: "Action", item_type: "Computing", parent_id: 4 under XRR-1 261014B). It then calls upload_file (file_type_id: 1) to attach XRR-fit_Co-C(261014B).xrcx (file_id = 8).
  5. Extract and store the 4 fit values (aps.xrcx v2): The agent calls extract_file_key_values on file_id = 8 and calls add_values on XRR fit 261014B to store the four Reader-sourced results (Table 19-1).
  6. Verify zero drift and wait for human acceptance: Finally, the agent runs check_value_drift (22 checked, 22 unchanged), check_storage (8 ok), and report_value_issues (count: 0). It then stops for the human owner to inspect and accept the fit in the Desktop window (Figure 19-2). Once accepted, it copies the fit into the production laboratory notebook (Item 12 under XRD in Project 3 Co/C).

Warning: why save_project must use curves.job_id without a typed structure

When XRC_MCP.exe saves an .xrcx file from a finished fit job via curves.job_id, it writes a [FITRESULT] block inside the archive that stores the fit χ2\chi^2χ2. If an agent instead passes a manually typed structure JSON to save_project, the file is written with [LASTFIT] and no valid χ2\chi^2χ2, so aps.xrcx cannot extract Chi2. Never type Chi2 by hand (Manual) to hide a missing [FITRESULT].
Going Deeper: how aps.xrcx v2 names main-stack versus surface-layer keys

An X-Ray Calc 3 model often has a thin surface contamination stack (N = 1, stack 1) above the main periodic stack ([Co/C] x 20, stack 2). In that case, the aps.xrcx reader (version 2) identifies the stack with the largest repeat count (N>1N > 1N>1) as the main stack. Its layers receive the bare key names Co Thickness and C Thickness (averaged over the 20 periods for a polynomial profile). Their sum is emitted as Period (49.40 A˚49.40\,\Ang49.40A˚, converted by factor 10−1010^{-10}10−10 to 4.940×10−9 m4.940 \times 10^{-9}\,\text{m}4.940×10−9m). Layers belonging to other stacks receive a stack suffix such as C Thickness (stack 1) (11.23 A˚11.23\,\Ang11.23A˚ for the surface layer) so they can never be confused with the multilayer period layers.
