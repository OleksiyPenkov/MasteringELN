Part 2 · Chapter 6

The Item Tree and Experiment Templates

In This Chapter

  • Choosing between Procedures, Specimens, and Actions for each step of an experiment
  • Adding missing Action Types and Equipment without leaving the item dialog
  • Selecting multiple items for batch value extraction, tagging, moving, or deletion
  • Creating and reusing Experiment Templates (.elntemplate) for repeatable workflows

In Chapter 4: Step 1: Build the whole item tree first, you built the six-item tree for Study A (261015A) by hand. Doing that click by click works for one sample, and gets old fast when you run a series of twenty coatings with the same tests. In this chapter, you’ll see how to nest multi-step experiments cleanly, run batch actions across many rows at once, and create a complete sample tree in seconds from an Experiment Template (.elntemplate).

Designing a clean item hierarchy

Every scientific record in the center Items panel is a Procedure (Proc), a Specimen (Item), or an Action (Action). Picking the right level and parent keeps your sample tree easy to read (Table 6-1):

  • Put a synthesis or deposition run at the root as a Procedure. In both Study A (Deposition 261015A) and Study B (Deposition 261014B), the sputtering run is a top-level Procedure. It creates the sample and holds the run-wide deposition conditions and logs.
  • Put a preparation step that happens before or during the run as a child Action of the Procedure. In Study B, plasma substrate cleaning (Cleaning 261014B) is a child Action under Deposition 261014B.
  • Put each physical sample produced by the run as a Specimen under the Procedure. If one deposition run coats both a silicon wafer and a steel coupon, list the substrates in the specimen description (as in 261015A). When the substrates serve different experimental purposes, create separate Specimen rows under the same Procedure.
  • Put every measurement or test on that sample as a child Action under the Specimen. In Study A, Thickness 261015A, Indentation 261015A, and Friction test 261015A sit directly under specimen 261015A.
  • Nest a follow-up measurement or analysis under the Action it depends on. In Study A, Wear track 261015A measures the groove created by Friction test 261015A, so it sits under Friction test 261015A. In Study B, XRR fit 261014B fits the curve measured in XRR-1 261014B, so it sits directly under XRR-1 261014B (Figure 1-2).

Remember

A file, a note, or a protocol is attached to an item; it is not a child item of its own. Always create the Action row for a measurement or fit first, then attach the file and extract its values onto that action.

Creating, duplicating, and moving items safely

When you create or edit a Procedure or Action (Item > New Procedure, Item > New Action, or Item > Edit), the dialog asks for Title, Description, Item type, Action type, and Equipment.

When you install a new instrument or start a new test, the drop-down list may lack your Action type or Equipment. You can add it inside the item dialog without opening Reference Data:

  1. Select an Item type first. This enables the + button right beside Action type (tooltip: Add a new action type). Click +, enter a non-blank Title, select a Kind, and click OK.
  2. Select an Action type that takes equipment. This enables the + button right beside Equipment (tooltip: Add new equipment). Click +, enter Model, Manufacturer, and Location (all three are required), and click OK.

In ELN

The APS ELN Community installer ships with empty equipment tables (Equipment.csv and ActionTypeEquipment.csv contain only the header and one blank row) because every laboratory has its own instruments. Use the + button beside Equipment the first time you record each instrument, or manage the full list under Reference Data.

To copy an existing item structure, select the item and choose Item > Duplicate. In the duplicate dialog, pick the destination folder and tick the option to link the copy to the original item if the new run is a repeat or continuation.

To move an item to a different parent or folder after creation, right-click the item and choose Move to…. Select the new parent item or destination folder from the list and click Move.

Warning: do not drag items onto each other to reorder siblings

In the center Items panel, dragging one item row onto another row can reparent the dragged item as a child of the target row. To change the manual display order of top-level root procedures, select the root procedure and press Ctrl+Up or Ctrl+Down (or use Move Up and Move Down). Child actions, files, and values are not reordered by Ctrl+Up or Ctrl+Down.

Working on multiple records at once

You can select several rows at once in the Items panel to run batch operations across an entire sample series:

  • Hold Ctrl and click to add or remove individual rows from your selection.
  • Hold Shift and click (or press Shift+Up and Shift+Down) to select a contiguous range of rows.
  • Right-click any row inside your selection to open the batch context menu while keeping all rows selected. (Right-clicking a row outside the selection switches the selection to that single row.)

When multiple records are selected, APS ELN disables single-item commands (New, Edit, Duplicate, Add File, Add Note, Add Protocol, Add Value, Links…). Instead, it enables six batch commands:

  1. Extract values (Extract values from N files…): groups the selected files by reader plugin and asks you to map the keys once per reader. It then extracts values across all matching files (Chapter 9: Reader mappings, unit factors, and standard deviations).
  2. Link to plan point…: matches selected top-level procedures to the free points of an active Experiment Series by their stored factor values (Chapter 12: Making or linking depositions and confirming planned values).
  3. Move to…: moves all selected items or files to a chosen destination.
  4. Tags…: assigns or removes tags across all selected items.
  5. Export: exports all selected files into a destination folder on disk, automatically appending (2), (3) if two files share the same display name so no file is ever overwritten.
  6. Delete: moves selected items to the Recycle Bin, or permanently deletes selected files and their extracted Reader values (Chapter 5: Deleting containers and using the Recycle Bin).

Every batch command shows a single confirmation dialog before it starts. If any selected row cannot be processed (for example, because an item is signed or sits in a read-only project), the confirmation names that row and the reason. It then skips that row safely and shows a summary report at the end.

Building and applying Experiment Templates

When your group runs a standard sequence of synthesis and characterization steps, save that tree as an Experiment Template (Figure 6-1).

APS ELN ships with ready-made .elntemplate files in Assets/Runtime/ExperimentTemplates/ (such as Deposition_Mechanical.elntemplate, Deposition_XRayOptics.elntemplate, Deposition_FullCharacterization.elntemplate, and Specimen_SurfaceMorphology.elntemplate). You can also build your own template in five steps:

  1. Choose Reference Data > Experiment Templates….
  2. Click Add, and choose whether the root of your template is a Procedure (Proc) or a Specimen (Item).
  3. Enter the template Name (for example, BN-DLC Tribology Standard), Category, and Description.
  4. Select the root node in the structure tree and set its Title, Level, Type, and Action Type. Use Add Child and Add Sibling to add the specimen and measurement action nodes (Thickness, Indentation, Friction test, and child Wear track).
  5. Click Save and inspect the hierarchy preview.

To start a new sample from your template:

  1. Select your destination project and folder in the Projects panel.
  2. Choose Item > New from Template….
  3. Pick the template from the list and check the hierarchy preview (which shows the levels, action types, and equipment).
  4. Enter the Experiment title (for example, Deposition 261015A) and click Create.

Tip

You can share experiment templates with colleagues or move them between a team server and a local Community notebook. In Reference Data > Experiment Templates…, click Export to save a template as an .elntemplate file, and use Import (or Import All… for a folder) to load .elntemplate files into another notebook.
Going Deeper: atomic template creation and Protocol vs. Experiment templates

Do not confuse Experiment Templates with Protocol Templates (Chapter 8: How protocol templates and AutoFill work):

  • An Experiment Template (.elntemplate, managed in Reference Data > Experiment Templates…) creates a multi-item tree of Procedures, Specimens, and Actions in the center Items panel. When you click Create in Item > New from Template…, APS ELN writes the entire hierarchy and its audit-log rows in one atomic transaction. If anything fails, no half-built tree is left behind.
  • A Protocol Template (.json, managed in Reference Data > Protocol Templates…) defines a structured form with sections, rows, and input fields that you attach to one item via Item > Add Protocol.
