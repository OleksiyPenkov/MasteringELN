## Why agent-written records need the Value Route

An audit of two earlier X-ray optics studies written by an AI agent in the author's laboratory (`T7` and `T8` in `arXiv:2610.27859`, Section 4.5) revealed an instructive failure mode:

- The agent attached the input files, ran the fits, and wrote detailed Markdown notes naming the source file, the job IDs, and the fitted thicknesses.
- However, across both studies, the agent stored **14 input condition values and 0 test result values**. Because the fitted period, layer thicknesses, and $\chi^2$ were written only in prose paragraphs instead of structured **Values** with a `Reader` source, they were invisible to the notebook's analysis and audit tools. Neither **Tools > Analysis...** (<a href={`${import.meta.env.BASE_URL}/ch13-charts-correlations-and-pdf-reports#plotting-conditions-against-results`}>Chapter 13</a>) nor `check_value_drift` (<a href={`${import.meta.env.BASE_URL}/ch16-reading-data-and-auditing-drift-via-mcp#running-the-three-project-wide-health-checks`}>Chapter 16</a>) could plot or verify a single result.

To prevent this, Study B enforces a strict **Value Route**: the agent is forbidden to type numbers by hand (`Manual` source) or leave results in prose only. Every stored number must come from calling `extract_file_key_values` on an attached file and passing the extracted fields verbatim to `add_values` with `source_kind: "Reader"` (<a href="#fig-17-1">Figure 17-1</a>).

## Part 1: The Record Agent builds Study B (`261014B`)

In Part 1 of Study B (`record_agent.md`), the Inbox (`--upload-root`) holds 7 raw files from the sputtering system and the X-ray diffractometer (<a href="#table-17-1">Table 17-1</a>). The Record Agent executes these steps through `ELNCommunityMCP.exe`:

1. **Verify catalog IDs:** Calls `list_file_types` (verifying `.json` is `19`, `.tsv` is `38`, and `.xrdml` is `10`) and `list_value_types`.
2. **Create the container and item tree:** Calls `create_project` (`"Study B: Co/C multilayer (demonstration)"`), `create_folder` (`"261014B"`), and `create_item` four times to build:
   - Item `1` (`Proc`, `Synthesis`): `Deposition 261014B`
   - Item `2` (`Action`, `Treatment`, parent `1`): `Cleaning 261014B`
   - Item `3` (`Item`, `Specimen`, parent `1`): `261014B` (description: `"Co/C multilayer, N = 20, on glass"`)
   - Item `4` (`Action`, `Measurement`, parent `3`): `XRR-1 261014B`
3. **Upload the 7 raw files:** Calls `upload_file` to attach the 3 deposition files to Item `1`, the 3 plasma-cleaning files to Item `2`, and `XRR-1_Co-C(261014B).xrdml` to Item `4`.
4. **Extract and store the 18 `Reader` values (`aps.deposition` v1):** Calls `extract_file_key_values` on `Deposition_2026-10-14_11-56-09.depo.json` (`file_id = 1`) and `Cleaning_(261014B)_2026-10-14_11-16-41.depo.json` (`file_id = 4`). Following the **Value Route**, it selects every key that has `is_key: true` and a mapped `value_type_id`, and calls `add_values` once per item:
   - **14 values on `Deposition 261014B`:** 12 conditions (`Deposition Conditions.P` $= 0.267\,\text{Pa}$ converted from $2\,\text{mTorr}$, `Pbase` $= 0\,\text{Pa}$, `ArFlow` $= 20\,\text{sccm}$, `N` $= 20$, `Layer Co.currentCo` $= 0.05\,\text{A}$ from $50\,\text{mA}$, `freqCo` $= 40000\,\text{Hz}$, `dutyCo` $= 70\%$, `timeCo` $= 42\,\text{s}$, `Layer C.currentC` $= 0.3\,\text{A}$ from $300\,\text{mA}$, `freqC` $= 50000\,\text{Hz}$, `dutyC` $= 60\%$, `timeC` $= 108\,\text{s}$) and 2 results (`Duration` $= 3626.42\,\text{s}$, `BasePressure` $= 5.10 \times 10^{-5}\,\text{Pa}$).
   - **4 values on `Cleaning 261014B`:** `Parameters.CleaningTime` $= 60\,\text{s}$, `Parameters.P` $= 0.200\,\text{Pa}$, `Duration` $= 138.71\,\text{s}$, and `BasePressure` $= 1.14 \times 10^{-4}\,\text{Pa}$.
5. **Run the three audit checks:** Calls `check_value_drift` (`18 checked, 18 unchanged`), `check_storage` (`7 ok`), and `report_value_issues` (`count: 0`).

<Remember>Three domain facts in Study B show why you should always extract from `.depo.json` with `is_key: true` rather than guessing from logs. First, `timeCo` ($42\,\text{s}$) and `timeC` ($108\,\text{s}$) are sputtering times rather than layer thicknesses. Second, the `Mean.*` keys in `.depo.json` average over the entire run window including pump-down, so they are not deposition setpoints. Third, the `.tsv` units header labels current columns as `A` when the numbers are in `mA`. Attach the `.tsv` for time-series plots, and extract values only from `.depo.json`.</Remember>

## Part 2: Fitting Agent records `XRR fit 261014B`

Once the raw scan `XRR-1_Co-C(261014B).xrdml` (`file_id = 7`) is in the notebook, the Fitting Agent (`fitting_agent.md`) fits the curve and records the fit back into APS ELN (<a href="#fig-17-1">Figure 17-1</a> and <a href="#table-17-1">Table 17-1</a>):

1. **Stage the `.xrdml` file out of ELN (`download_file`):** When an attachment exists only inside ELN storage, an agent calls `download_file` with `file_id` and a `dest_path` inside the allowed `--upload-root`. The server verifies project read access, copies the bytes out, checks the MD5 hash against `stored_hash`, and returns `storage_status: "ok"` without altering notebook state.
2. **Assess and fit the curve in X-Ray Calc 3 (`XRC_MCP.exe`):** Using the laboratory fitting procedure covered in *Mastering XRR Fitting*, the agent calls `assess_xrr` and builds the starting model (`SodaLimeGlass` substrate / $[\text{C} / \text{Co}] \times 20$ / surface $\text{C}$ contamination layer). It scans resolution ($\Delta\theta = 0.014^\circ$) and runs 5-seed Periodic and Polynomial order 1 fits (`fit_xrr`, `job_wait`, `job_result`, verified by `check_acceptance.py`). Because the period drift across the 20 periods ($\Delta D = -0.336\,\Ang$) exceeds twice the 5-seed spread ($0.064\,\Ang$), the Polynomial order 1 fit (`fit-20261016-153456-ea29`, $\chi^2 = 0.943$) is accepted.
3. **Save `.xrcx` with `curves.job_id` so `[FITRESULT]` is written:** The agent calls `save_project` passing `curves.job_id = "fit-20261016-153456-ea29"` and *without* a manual `structure` override, writing `XRR-fit_Co-C(261014B).xrcx` (MD5 `106D0EFC42C3B0A200FFD9BE087BB1A5`) with `"fit_record": "FITRESULT"`.
4. **Create `XRR fit 261014B` and upload the `.xrcx` file:** Back in `ELNCommunityMCP.exe`, the agent calls `create_item` to create child action `XRR fit 261014B` (`Item 5`, `level: "Action"`, `item_type: "Computing"`, `parent_id: 4` under `XRR-1 261014B`), and calls `upload_file` (`file_type_id: 1`) to attach `XRR-fit_Co-C(261014B).xrcx` (`file_id = 8`).
5. **Extract and store the 4 fit values (`aps.xrcx` v2):** The agent calls `extract_file_key_values` on `file_id = 8` and calls `add_values` on `XRR fit 261014B` to store the four `Reader`-sourced results (<a href="#table-17-1">Table 17-1</a>).
6. **Verify zero drift and wait for human acceptance:** Finally, the agent runs `check_value_drift` (`22 checked, 22 unchanged`), `check_storage` (`8 ok`), and `report_value_issues` (`count: 0`). It then stops for the human owner to inspect and accept the fit before copying the accepted fit into the production laboratory notebook (`Item 12` under `XRD` in Project 3 `Co/C`).

<Warning title="why save_project must use curves.job_id without a typed structure">When `XRC_MCP.exe` saves an `.xrcx` file from a finished fit job via `curves.job_id`, it writes a `[FITRESULT]` block inside the archive that stores the fit $\chi^2$. If an agent instead passes a manually typed `structure` JSON to `save_project`, the file is written with `[LASTFIT]` and no valid $\chi^2$, so `aps.xrcx` cannot extract `Chi2`. Never type `Chi2` by hand (`Manual`) to hide a missing `[FITRESULT]`.</Warning>

<GoingDeeper title="how aps.xrcx v2 names main-stack versus surface-layer keys">

In an X-Ray Calc 3 model that has a thin surface contamination stack (`N = 1`, stack 1) above the main periodic stack (`[Co/C] x 20`, stack 2), the `aps.xrcx` reader (version 2) identifies the stack with the largest repeat count ($N > 1$) as the **main stack**. Its layers receive the bare key names `Co Thickness` and `C Thickness` (averaged over the 20 periods for a polynomial profile), and their sum is emitted as `Period` ($49.40\,\Ang$, converted by factor $10^{-10}$ to $4.940 \times 10^{-9}\,\text{m}$). Layers belonging to other stacks receive a stack suffix such as `C Thickness (stack 1)` ($11.23\,\Ang$ for the surface layer) so they can never be confused with the multilayer period layers.

</GoingDeeper>
