Appendices · Appendix E

Glossary

In This Chapter

  • Definitions of APS ELN and data-provenance terms in alphabetical order
  • Cross-references to the chapters where each concept is introduced

Each entry defines a term as this book uses it and links to the chapter section where it is introduced. Toolbar and tree icons are listed in Appendix A. Viewer plugins and file extensions are listed in Appendix B. Value sources, units, and formulas are listed in Appendix C.

A

Action (Action). A preparation, treatment, measurement, test, or analysis step in the scientific hierarchy, placed below a Procedure, a Specimen, or a parent Action. See Chapter 3: Reading the item tree and its row buttons; Chapter 6: Designing a clean item hierarchy.

Analysis snapshot (analysis_snapshot). A JSON object stored on a Reader value that records the exact viewer evaluation state used when the number was extracted. Examples include the pixel rectangles (regions) in a .fibps height map, the ticked indents in a .mit nanoindentation file, and the cycle interval and file hash in a .zrw friction file. See Chapter 7: Table 7-1; Chapter 20: Passing viewer selections and Derived inputs.

Audit log. The chronological table of Create, Update, and Delete operations across the notebook, inspected via Tools > Audit Log… or get_audit_log. See Chapter 16: Inspecting the Audit Log.

AutoFill. A binding on a protocol template field (such as values.all, conditions.all, results.all, or values.<Symbol>). It copies a snapshot of the owning item’s values or metadata into the form when the protocol is created. See Chapter 8: How protocol templates and AutoFill work.

C

Check Value Sources (check_value_drift). A verification command that re-runs the current data file readers on the source files of all Reader values in an item subtree. It also recalculates all Derived values recursively from their inputs and reports any drift or changed selections. See Chapter 9: Checking value sources and understanding drift codes; Chapter 18: Running the three project-wide health checks.

Completeness rules. Rules configured in Tools > Completeness Rules… that specify which Required File Types and Required Value Types must exist on an item for a given Action Type and Equipment. Checked via Tools > Data Completeness…. See Chapter 16: Completeness rules and Data Quality Checks.

Compound extension. A multi-part filename ending such as .depo.json or .process.log that routes the attachment to a specialist viewer (Deposition or Process Log) rather than a generic .json or .log viewer. See Chapter 7: How file attachment and extension routing work.

Condition (EXP_CONDITION). A numeric value that records an experimental input or setpoint, such as sputtering power, gas pressure, deposition time, normal load, or cycle count. Plotted on the horizontal (XXX) axis in Tools > Analysis…. See Chapter 9: Conditions, Results, units, and plausible-range checks.

Content seal (Sealed). A checksum computed over a closed or accepted hypothesis’s statement, change description, conclusion, outcome, attached runs, and cited evidence (Close with conclusion in Community or Accept in Commercial). See Chapter 11: Concluding, closing or accepting, and checking the content seal.

D

Data file reader (DFR). The code inside a viewer plugin that extracts numeric keys and units from an attached file. Each reader is identified by reader_id and integer reader_version (such as aps.deposition v1, aps.fibps v3, aps.mit v2/v3, aps.zrw v2, or aps.xrcx v2). See Chapter 9: Reader mappings, unit factors, and standard deviations; Appendix B.

Derived value (Derived). A numeric value calculated by APS ELN from stored input values using a versioned server formula (such as wear_rate_reciprocating version 1), storing the formula_id, formula_version, and input value_id list. See Chapter 9: The four value sources and Derived formulas.

E

Electronic signature (SIGNED). A permanent cryptographic seal applied to an item via Signature > Sign Item… with a user password and meaning (Authored, Reviewed, Approved, or Witnessed). Locks the item against all further edits. See Chapter 16: Signing an item and verifying signature integrity.

Experiment template (.elntemplate). A reusable hierarchy blueprint managed in Reference Data > Experiment Templates… and applied via Item > New from Template… to create a complete Procedure -> Specimen -> Action tree in one atomic operation. See Chapter 6: Building and applying Experiment Templates.

F

Folder. A container inside a project in the left Projects panel that organizes procedures and specimens. Distinct from scientific items in the center Items panel. See Chapter 5: How Groups, Projects, and Folders fit together.

Format 6. The current local SQLite schema version used by APS ELN Community, supporting Derived value provenance, experiment series (Project > Series…), default reader mappings, and tribology value types. See Chapter 2: Creating a local notebook in Community.

G

Group. A top-level organizational heading in the left Projects panel (Project > New Group) that groups projects visually without holding scientific records or affecting permissions. See Chapter 5: How Groups, Projects, and Folders fit together.

H

Hypothesis. A project record (Project > Hypotheses, opened in its own window) that links an expectation (Proposal), the experimental items that test it (Runs), the cited files and values (Evidence), and the final outcome (Conclusion). In Community, hypotheses move Draft -> Open -> Closed; in Commercial, they move Proposed -> Approved -> In review -> Accepted. See Chapter 11: Why connect experiments to a hypothesis tree?.

M

Manual value (Manual). A value whose number was typed by a person in Item > Add Value (or edited by hand after extraction), carrying no automated reader or formula link. See Chapter 9: The four value sources and Derived formulas.

Model Context Protocol (MCP). The line-based JSON-RPC 2.0 standard over stdio used by ELNCommunityMCP.exe and ELNMCPServer.exe to expose notebook tools to AI assistants. See Chapter 17: What the ELN MCP server does.

P

Planned value (Planned). A condition value written onto a procedure by Make deposition… in an Experiment Series before the run is confirmed. Displayed in grey italic (planned), excluded from series plots and CSV exports, refused as hypothesis evidence, and refused as a Derived formula input until confirmed with Confirm planned values in the Desktop GUI. See Chapter 12: Making or linking depositions and confirming planned values.

Procedure (Proc). A top-level experimental record in a project or folder representing a synthesis, deposition run, or experimental campaign (such as Deposition 261015A). See Chapter 3: Table 3-1; Chapter 6: Designing a clean item hierarchy.

Protocol. A structured form (or free-text entry) attached to an item via Item > Add Protocol and reviewed through Draft, In Review, Approved, and Rejected states. See Chapter 8: Adding and completing a protocol on an item.

R

Reader value (Reader). A value extracted from an attached file by a data file reader, recording source_file_id, file MD5, reader_id, reader_version, key_name, reader_units, conversion_factor, and optional analysis_snapshot. See Chapter 9: The four value sources and Derived formulas.

Result (TEST_RESULT). A numeric value that records a measured observation or calculated output, such as step height, hardness, friction coefficient, wear rate, or fitted period. Averaged on the vertical (YYY) axis in Tools > Analysis…. See Chapter 9: Conditions, Results, units, and plausible-range checks.

S

Search by meaning (search_semantic). The hybrid semantic search engine (ELN.Search), running offline on your PC in Community (.search.sqlite) or on the shared laboratory search server in the Team edition (notebook.search.sqlite). It indexes record text and attached documents (.pdf, .docx, .pptx, .xlsx, .md, .html, .json, .xml, .csv, .rtf, .txt) and optionally re-ranks the top 20 item groups with a cross-encoder model. See Chapter 14: Searching by meaning (Semantic Search) and reranking.

Series (Experiment Series). A project-level experimental plan, table, and plot window (Project > Series…) that defines 1 to 7 varied Factors (with optional labels and levels), Point generation (Full grid, Taguchi orthogonal array L4–L27, or No initial points), Fixed conditions, and Responses, and displays all linked depositions in a unified Table and Plot (including Level means (Taguchi) with Δ\DeltaΔ and rank) with OriginLab export. See Chapter 12: Planning a series in the Series window.

Specimen (Item). A physical sample, substrate piece, or model produced or studied inside a Procedure (such as 261015A or 261014B), holding child measurement and test Actions. See Chapter 3: Table 3-1.

T

Taguchi orthogonal array. A fractional factorial design table (L4, L8, L9, L16, L18, or L27) in Project > Series… where every level of each factor and every pair of levels of any two factors occur equally often, allowing 2 to 7 factors to be screened in 4 to 27 runs. See Chapter 10: Sweeps, full grids, and Taguchi orthogonal arrays.

Tolerance. A non-negative numeric field on a stored value, expressed in the stored unit of the Value Type. Automatically populated from <Key> STD during reader extraction. See Chapter 9: Reader mappings, unit factors, and standard deviations.

U

Upload root (--upload-root / MCPUploadRoot). The local folder to which MCP file uploads (upload_file) and file downloads (download_file) are strictly confined. See Chapter 17: Security, upload-root, and review boundaries.

V

Value Route. The laboratory rule for agent-written records requiring every stored number to come from extract_file_key_values (Reader source) or add_derived_value (Derived source) with zero hand-typed Manual values. See Chapter 19: Why agent-written records need the Value Route.

W

Wiki page. A Markdown-backed item of type Wiki stored inside one of the five standard project Wiki folders (Goals, Ideas, Literature, Analysis, References). See Chapter 13: The five-section Project Wiki.

Working draft. The separate local copy created when an attached file is opened in an external program or the Markdown Editor, saved back into notebook storage via Tools > Save Attachment Working Draft. See Chapter 7: Working drafts, external edits, and conflict resolution.
