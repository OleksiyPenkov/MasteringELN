Part 5 · Chapter 19

Ten Mistakes That Break Your Data Trail

In This Chapter

  • Ten real laboratory mistakes that silently break provenance
  • How each mistake shows up in APS ELN
  • Which chapter and check prevent each one

A notebook can look full on screen and still fail the moment you try to trace a published number back to its raw instrument curve. The ten mistakes below come directly from daily laboratory work and student onboarding for Study A (261015A) and Study B (261014B).

1. Leaving an action empty

A student creates a Friction test or Thickness action in the item tree before going to the instrument, runs the measurement, leaves the file on a USB drive, and forgets to attach it. Months later, the action row is still an empty placeholder. Build the whole tree at the start of the experiment so every planned measurement is visible. Then run Tools > Data Completeness… (Chapter 14: Completeness rules and Data Quality Checks) before you finish the day so no action stays empty.

2. Attaching a screenshot instead of raw data

Saving a .png or .jpg screenshot of an X-Ray Calc fit window or a nanoindenter screen gives a picture that no data file reader can parse. You cannot extract Reader values from a screenshot, you cannot re-evaluate its cycle interval or indent selection, and Check Value Sources… cannot verify a single number against it. Always attach the native raw file (.depo.json, .tsv, .fibps, .mit, .zrw, .xrdml, .xrcx; Chapter 7: Inside the five core instrument viewers).

3. Putting result numbers in a file name

Naming a file BN-DLC-351.9nm.fibps or wear-4.3E13nm3.fibps puts an unverified number into a filename string. If you later adjust the step-height rectangles in the FIBPS viewer or fix a calibration factor, the stored Value updates while the filename still shows the old number. Name every file after the sample code, the measurement, and the position (1.fibps, wear 1.fibps, BN-DLC(261015A).mit), and store results as typed Values (Chapter 1: Four rules that keep your data trail unbroken).

4. Typing a number that a reader can extract

When a student reads Hardness = 5.92 GPa off the MIT viewer and types 5.92 into Item > Add Value by hand, APS ELN records the value with source kind Manual instead of Reader. That value has no link to BN-DLC(261015A).mit, no reader_version, and no record of which indents were ticked. Use Extract Values (or extract_file_key_values + add_values in MCP) whenever a reader plugin supports your file (Chapter 9: Reader mappings, unit factors, and standard deviations).

5. Typing a value before attaching its file

If you type a number into the notebook right after a measurement and plan to upload the raw file later, that file often stays on the instrument PC forever. Make the order strict: create the Action, attach the File (Chapter 4: Step 2), and extract the Values from that attached file (Chapter 4: Step 3).

6. Hiding results inside prose notes

Writing fitted thicknesses, χ2\chi^2χ2, or hardness averages inside a Markdown text note leaves zero result Values on the action. Prose notes are invisible to Tools > Analysis… (Chapter 13), invisible to query_values and correlate_values (Chapter 16), and invisible to drift checks. Write your narrative in notes and Wiki pages, and always store the numbers themselves as Values.

7. Putting a fit under the wrong sample

An analysis project file (such as XRR-fit_Co-C(261014B).xrcx or a Wear track action) belongs to the specific measurement action it analyzed. If you attach a fit of sample 261014B under sample 261014A, Tools > Analysis… will pair 261014B’s period with 261014A’s deposition conditions. Always create XRR fit <Code> as a child action of XRR-1 <Code> (Chapter 6: Designing a clean item hierarchy) and include the sample code in both the action title and the .xrcx filename.

8. Mixing angstroms, nanometers, and meters

X-ray multilayer thicknesses are quoted in ångströms (A˚\AngA˚), while optical profiler step heights are displayed in nanometers (nm\text{nm}nm) or micrometers (μm\mu\text{m}μm). General Thickness and Period value types in the database store meters (m\text{m}m). Meanwhile, the .tsv sputtering log in Study B labels current columns as A when the numbers are mA. Never convert units in your head and type the result. Let Extract Values apply the verified reader mapping factor (10^-10 for A˚→m\Ang \rightarrow \text{m}A˚→m, 0.001 for mA→A\text{mA} \rightarrow \text{A}mA→A), and check the conversion line in the dialog (Chapter 9).

9. Renaming storage files in Windows Explorer

Your notebook database tracks every attached file by its relative storage path and MD5 checksum. If you open the <name> files attachment directory in Windows Explorer and rename, move, or edit a file directly on disk, check_storage will report missing or content_mismatch. Always rename, replace, or move attachments inside APS ELN using Edit, Reupload…, or Move to… (Chapter 7: Replacing, moving, exporting, and viewing files).

10. Backing up the database without its files

Copying notebook.sqlite onto a backup drive without copying its <name> files attachment folder saves your item titles and numbers while leaving every raw curve and image behind. Worse, exported PDF reports and JSON scientific packages (File > Export...) do not contain raw attachment bytes either (Chapter 13: Table 13-1). Always close APS ELN and copy the .sqlite file and its entire attachment folder together (Chapter 2: How to back up a local notebook safely).
