Instead of clicking through menus for every repetitive check, you can connect an AI assistant such as Claude Code or Codex to APS ELN through the **Model Context Protocol (MCP)** server. The assistant can search across projects, inspect time-series logs, and audit every stored value against its raw file in seconds. It can also fit an X-ray reflectivity curve (<a href={`${import.meta.env.BASE_URL}/ch17-study-b-xrr-fitting-with-provenance#part-2-fitting-agent-records-xrr-fit-261014b`}>Chapter 17</a>) and build structured experiment trees (<a href={`${import.meta.env.BASE_URL}/ch18-drafting-trees-hypotheses-and-wikis#passing-viewer-selections-and-derived-inputs`}>Chapter 18</a>), all under the server's built-in safety boundaries (<a href="#fig-15-1">Figure 15-1</a>).

## What the ELN MCP server does

Both editions of APS ELN include a command-line MCP host executable installed right beside the Desktop program (<a href="#fig-15-1">Figure 15-1</a>):

- **`ELNCommunityMCP.exe` (APS ELN Community):** opens a local format 5 `.sqlite` notebook and its attachment folder on your computer.
- **`ELNMCPServer.exe` (APS ELN "For Teams"):** connects to your shared laboratory MySQL and WebDAV server using your workstation's configuration.

<Figure id="fig-15-1" number="15-1" src={`${import.meta.env.BASE_URL}/figures/fig-15-1-mcp-architecture.svg`} alt="Architecture diagram showing AI Client (Claude Code / Codex) talking over line-based JSON-RPC stdio to the ELN MCP Host (ELNCommunityMCP.exe or ELNMCPServer.exe with 26 viewer plugins), which accesses the Notebook DB, Attachment Store, and --upload-root sandbox under strict guardrails" caption="How an AI assistant connects to APS ELN. The client launches the MCP host over standard input/output (stdio). The host loads the same 26 viewer plugins (.bpl) and enforces project scope, signed-item locks, upload-root confinement, and human review gates." />

When an AI client starts the MCP host, they communicate over standard input and standard output (`stdio`) using one UTF-8 JSON-RPC 2.0 message per line. The MCP host loads the same scientific domain model and the same 26 `.bpl` viewer plugins as the Desktop GUI. Calling `extract_file_key_values` from an agent therefore runs the exact same reader code (`aps.deposition`, `aps.fibps`, `aps.mit`, `aps.zrw`, `aps.xrcx`) as clicking **Extract Values** on screen (<a href={`${import.meta.env.BASE_URL}/ch9-values-units-formulas-and-provenance#reader-mappings-unit-factors-and-standard-deviations`}>Chapter 9: Reader mappings, unit factors, and standard deviations</a>).

## Preparing a local session in APS ELN Community

In **APS ELN Community**, the installer places `ELNCommunityMCP.exe` in `%LocalAppData%\Programs\ELN Community` right next to `ELNCommunity.exe`. Follow these steps to prepare a local MCP session safely:

1. **Create your notebook in the Desktop program first, then close the Desktop.** A local Community notebook uses a single-user SQLite file. Close `ELNCommunity.exe` before starting an MCP session that writes to that same `.sqlite` file.
2. **Create a dedicated upload/staging folder (`--upload-root`).** Create an ordinary local folder (such as `C:\ELN\Inbox`) with no directory junctions or symbolic links. Place only the raw measurement files you want the agent to upload (or the files exported by `download_file`) inside this folder.
3. **Configure your MCP client with absolute paths:**

```text
ELNCommunityMCP.exe --notebook "C:\ELN\notebook.sqlite" --upload-root "C:\ELN\Inbox" --plugins "C:\Users\<you>\AppData\Local\Programs\ELN Community\Plugins"
```

If your `.sqlite` notebook already remembers its attachment folder (<a href={`${import.meta.env.BASE_URL}/ch2-opening-a-notebook#creating-a-local-notebook-in-community`}>Chapter 2: Creating a local notebook in Community</a>), `ELNCommunityMCP.exe` uses that saved folder automatically. If not, pass `--storage "C:\ELN\notebook files"` as well.

<Warning title="never pass --config to ELNCommunityMCP.exe">`--config` is a Desktop-only flag (`ELNCommunity.exe`). `ELNCommunityMCP.exe` takes `--notebook`, `--upload-root`, `--plugins`, and optional `--storage`, and it only opens an existing format 5 notebook; it never creates or migrates a database.</Warning>

## Registering with Claude Code in a team laboratory

In a team laboratory running the Commercial edition, the installer places `ELNMCPServer.exe` in `C:\Program Files\E-LabNotebook3\`.

<InTeamLab title="registering ELNMCPServer.exe with Claude Code and clicking eln:// links">

`ELNMCPServer.exe` reads your server connection settings, credentials, WebDAV URL, and upload root directly from the Windows Registry configured by the Desktop client. You can therefore register it globally in Claude Code with one command:

```text
claude mcp add -s user eln -- "C:\Program Files\E-LabNotebook3\ELNMCPServer.exe"
```

Run `claude mcp list` to verify that `eln: C:\Program Files\E-LabNotebook3\ELNMCPServer.exe (user)` appears. (If you upgraded from an older 32-bit build in `C:\Program Files (x86)\E-LabNotebook3\`, run `claude mcp remove -s user eln` first and re-register the 64-bit path.)

Every MCP tool that returns an item (`list_items`, `get_item`, `create_item`, `update_item`) includes a clickable `url` field such as `eln://item/42`. Because the Desktop client registers the `eln://` protocol handler in Windows on startup, clicking `eln://item/42` in a Markdown-rendering chat window focuses the Desktop application and jumps straight to item 42.

</InTeamLab>

<Tip>In the Commercial Desktop client, right-click any project, folder, or item in the tree and choose **Copy MCP Link**. Paste that reference directly into your chat prompt so your AI assistant knows the exact project or item ID without searching.</Tip>

## Security, upload-root, and review boundaries

An AI agent can make fast, persistent changes to a notebook, so the ELN MCP server enforces five hard boundaries inside its own code (<a href="#fig-15-1">Figure 15-1</a>):

1. **Project and account scope:** Every tool call reloads the active user principal and checks project permissions. Attempting to read or write an item or file in a project you cannot access returns the same `out of scope` error as a non-existent ID. An agent cannot probe private projects.
2. **Upload-root file confinement (`--upload-root` / `MCPUploadRoot`):** Both `upload_file` (reading a local file into ELN) and `download_file` (copying an attached file out of ELN) are strictly confined to `--upload-root`. The server refuses any path outside that folder, any `..` traversal, any Windows device prefix (`\\?\`, `\\.\`), any alternate data stream, or any directory junction/symlink along the path. Never set `--upload-root` to `C:\` or your entire user profile.
3. **Signed-item and cited-item locks:** The MCP server refuses to edit, add values to, replace files on, or delete any item carrying an electronic signature (`SIGNED`, <a href={`${import.meta.env.BASE_URL}/ch14-completeness-audit-and-signatures#signing-an-item-and-verifying-signature-integrity`}>Chapter 14</a>). It also refuses to delete files or values cited by a hypothesis in `InReview` or `Accepted` (<a href={`${import.meta.env.BASE_URL}/ch10-the-hypothesis-tree-and-evidence#submitting-a-conclusion-and-checking-the-content-seal`}>Chapter 10</a>).
4. **Read-only session mode:** A read-only MCP session hides all write tools from `tools/list` and refuses any call that modifies data (`Tool "name" is not available in a read-only session.`). All read and audit tools (`list_projects`, `get_item`, `get_values`, `search`, `check_value_drift`, `check_storage`) remain available.
5. **No MCP tools for human review gates:** Calling `approve_hypothesis` or `accept_conclusion` returns `tool-not-found`. Approving protocols (<a href={`${import.meta.env.BASE_URL}/ch8-filling-out-protocols-and-checklists#the-protocol-review-workflow`}>Chapter 8</a>), approving or accepting hypotheses (<a href={`${import.meta.env.BASE_URL}/ch10-the-hypothesis-tree-and-evidence#proposing-a-hypothesis-and-passing-the-first-gate`}>Chapter 10</a>), and signing items (<a href={`${import.meta.env.BASE_URL}/ch14-completeness-audit-and-signatures#signing-an-item-and-verifying-signature-integrity`}>Chapter 14</a>) can only be performed by a human in the GUI.

<GoingDeeper title="line-based JSON-RPC stdio initialization">

When an MCP client launches `ELNCommunityMCP.exe` or `ELNMCPServer.exe`, it sends an `initialize` request line, followed by `notifications/initialized`. It then calls `tools/list` to read the JSON Schema of every registered tool before making any `tools/call` request:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_projects","arguments":{}}}
```

Diagnostic messages from viewer packages go to `stderr` so `stdout` carries pure JSON-RPC lines, and closing `stdin` terminates the server cleanly.

</GoingDeeper>
