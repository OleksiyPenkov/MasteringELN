Part 2 · Chapter 9

Values, Units, Formulas, and Provenance

In This Chapter

  • Recording Conditions and Results with the right Value Type, unit, and tolerance
  • Mapping reader keys and converting units automatically during Extract Values
  • Computing Derived values from stored inputs with server formulas
  • Auditing your items with Check Value Sources to catch drift and changed selections

If you only attach raw files, your notebook is just a file folder. Storing Values turns it into a searchable database (Chapter 1: The four links in every laboratory result). When you save every deposition pressure, layer thickness, hardness, friction coefficient, and wear rate as a typed value with its unit, tolerance, and source, APS ELN can average repeated scans in the item tree, plot correlations across samples, and verify months later that every number still matches its raw file.

Conditions, Results, units, and plausible-range checks

Every value stored on a Procedure or Action has one of two record types:

  • Condition (EXP_CONDITION): an experimental input or setting you chose for the run. Examples include sputtering pressure (0.267 Pa0.267\,\text{Pa}0.267Pa), target power (134 W134\,\text{W}134W), bias voltage (8 V8\,\text{V}8V), normal force (Fn=9.81 NF_n = 9.81\,\text{N}Fn​=9.81N), and cycle count (N=1000N = 1000N=1000).
  • Result (TEST_RESULT): an outcome measured by the instrument or calculated from measurements. Examples include base pressure (9.10×10−5 Pa9.10 \times 10^{-5}\,\text{Pa}9.10×10−5Pa), coating step height (3.58×10−7 m3.58 \times 10^{-7}\,\text{m}3.58×10−7m), indentation hardness (5.92±0.47 GPa5.92 \pm 0.47\,\text{GPa}5.92±0.47GPa), coefficient of friction (0.528±0.0190.528 \pm 0.0190.528±0.019), wear rate (K=3.05×10−7 mm3/(N⋅mm)K = 3.05 \times 10^{-7}\,\text{mm}^3/(\text{N}\cdot\text{mm})K=3.05×10−7mm3/(N⋅mm)), and fitted XRR period (D=4.94×10−9 mD = 4.94 \times 10^{-9}\,\text{m}D=4.94×10−9m).

Always extract values from attached files when a reader plugin supports your format (Reader mappings, unit factors, and standard deviations). When you need to record a condition or measurement that has no file reader (such as a substrate batch weight or a manual micrometer reading), choose Item > Add Value:

  1. Select the Procedure or Action in the Items panel and choose Item > Add Value (or open Item > Edit, switch to the Values tab, and click Add).
  2. Select the Category and Value type. Each value type displays its symbol, title, and stored unit (from ValueTypes.csv, managed in Reference Data > Value Types…).
  3. Under Record type, choose Condition or Result.
  4. Enter the Value in the stored unit (or click Convert… to convert from another compatible unit of the same physical quantity).
  5. Enter a numeric Tolerance in the stored unit (with no unit suffix) and a clear Description, then click Save.

Warning: value edits inside an existing item dialog save immediately

When you open an existing Procedure or Action with Item > Edit and add, edit, or delete a row on its Values tab, that value change is written to the database immediately. Clicking Cancel on the parent procedure/action dialog does not undo value changes already made on the Values tab.

Before saving any value, APS ELN checks the number and its tolerance against three plausible-range rules defined on its Value Type:

  1. Out of range: the value lies below the minimum or above the maximum configured for that value type in Reference Data > Value Types….
  2. Tolerance larger than the value: the tolerance exceeds the magnitude of the value itself (for example, a value of 2.28×10−52.28 \times 10^{-5}2.28×10−5 with a tolerance of 0.06020.06020.0602).
  3. Tolerance scale mismatch: a non-zero tolerance is more than the configured tolerance factor (default 1000×1000\times1000×) smaller than the value (for example, a value of 300300300 with a tolerance of 0.00010.00010.0001).

If any rule triggers during Add Value or interactive Extract Values, APS ELN names the issue. You can store the value anyway (Yes) or return to the dialog to fix the unit or value type (No). Automatic background extraction after Add File cannot prompt you, so it skips out-of-range values until you run Extract Values interactively on that file.

Reader mappings, unit factors, and standard deviations

Click Extract Values in a viewer (Chapter 7: Inside the five core instrument viewers) or right-click multiple files in the tree and choose Extract values from N files… (Chapter 6). APS ELN matches each key emitted by the reader plugin to a notebook Value Type:

  • Automatic unit conversion: When the reader’s unit and the target Value Type’s stored unit measure the same physical quantity, the dialog converts the number automatically. It shows the conversion factor right above Category. In Study B (261014B), the deposition reader (aps.deposition) emits sputtering pressure in mTorr, which ELN multiplies by 0.1333220.1333220.133322 to store Pa. It also emits coil current in mA and multiplies by 0.0010.0010.001 to store A. In aps.fibps, wear area in μm2\mu\text{m}^2μm2 converts to mm2\text{mm}^2mm2 (×10−6\times 10^{-6}×10−6).
  • Ambiguous or offset units are never guessed: Because the letter A means ampere to the general unit parser, an ångström (A) key requires an explicit reader mapping rule (10^-10 to m). Offset temperatures (∘C^\circ\text{C}∘C to K\text{K}K) are also not auto-converted.
  • Pattern rules with <Material>: In Reference Data > Value Types… > Reader mappings…, pattern rules such as <Material> Thickness or Layer <Material>.<Any> map layer keys for any element or compound. For Co Thickness and C Thickness in Study B, the rule places the material name (Co or C) in the value’s Description automatically.
  • Automatic <Key> STD pairing: Many readers emit both <Key> and <Key> STD with the same unit, such as Hardness and Hardness STD from aps.mit, COF and COF STD from aps.zrw, or Step Height and Step Height STD from aps.fibps. APS ELN multiplies the standard deviation by the same unit factor and stores it in the Tolerance field of the main value.

Tip

Keep Remember choices for this reader ticked at the bottom of the Extract Values dialog. When you click OK, APS ELN saves your key-to-Value-Type mappings in Reference Data > Value Types… > Reader mappings… so future files from that instrument map with one click.

Remember

An item keeps at most one Reader value for each key of each attached file. Extracting values from the same file a second time updates the existing Reader value in place instead of adding a duplicate row. Deleting an attached file automatically deletes the Reader values that came from that file while leaving Manual values untouched.

The four value sources and Derived formulas

Every value in APS ELN records how its number entered the notebook (Figure 9-1):

  1. Reader: extracted from an attached file. It records the file_id, the file’s MD5 hash, the reader_id and reader_version, the original key name, the emitted unit, and the applied conversion factor. It also stores any viewer analysis snapshot (such as ticked indents in .mit, step rectangles in .fibps, or the applied cycle interval in .zrw).
  2. Derived: calculated by APS ELN from stored input values using a versioned formula (formula_id, formula_version, and input value_id list).
  3. Manual: typed by hand in Add Value, or created when a user edits the number or tolerance of an existing Reader, Derived, or Planned value.
  4. Planned: written onto a procedure when you create a deposition from an Experiment Series (Project > Series…, Chapter 13). It appears in grey italic (planned) and cannot be plotted or used as an input to a Derived formula until you confirm it via Confirm planned values (or edit the value) after the run finishes.
  5. Unknown: recorded in an older notebook before value-level source tracking was introduced.

In ELN

When you select any value on the Values tab of Item > Edit, the source line at the bottom of the dialog shows its origin (Figure 9-2). For a Reader value, the Go to file button becomes active: clicking Go to file and confirming Yes closes the dialog and opens that exact source file in the Content Viewer.

To compute a Derived value (as you did for Study A’s reciprocating wear rate in Chapter 4: Step 4: Compute the Derived wear rate):

  1. Right-click the Procedure or Action and choose Add > Derived Value….
  2. Select the formula (wear_rate_reciprocating, version 1: K=A/(2⋅Fn⋅N)K = A / (2 \cdot F_n \cdot N)K=A/(2⋅Fn​⋅N), returning Wear rate in mm3/(N⋅mm)\text{mm}^3/(\text{N}\cdot\text{mm})mm3/(N⋅mm)).
  3. Select the stored input value(s) for each role (area in mm2\text{mm}^2mm2, normal_force in N\text{N}N, and cycles) from the item or its child actions. When you select two or more Wear area values with Ctrl+click or Shift+click, the dialog uses their mean and records every selected value_id in the Derived source.
  4. Click Save. You cannot type or alter the calculated number in Add > Derived Value….

Warning: a Derived value is a stored snapshot, not a live spreadsheet cell

If you later edit or delete one of the input values that fed a Derived value, APS ELN does not silently overwrite the historical Derived number. Instead, Check Value Sources… flags input_changed or input_missing so you can inspect the change and create a new Derived value if needed.

Checking value sources and understanding drift codes

Before you sign an experiment or cite its numbers in a paper, right-click the root Procedure in the Items panel and choose Check Value Sources…. You can also run check_value_drift through MCP in Part 4.

APS ELN re-reads every source file of every Reader value in the subtree using the currently installed viewer plugins, and re-calculates every Derived value recursively from its inputs. If all values match, a dialog reports how many values were verified with zero differences. If any value differs, a table lists the value ID, item, file, key, stored vs. current numbers, and the diagnostic code (Table 9-1).

Table 9-1: Diagnostic codes reported by Check Value Sources… (check_value_drift).

Status codeApplies toWhat changed and how to resolve it
value_changedReader / DerivedRe-running the reader or formula today gives a different number than the stored value. Re-extract or create an updated Derived value if the new reader/input is intended.
reader_version_changedReaderThe installed plugin has a newer reader_version than the version recorded when the value was extracted (for example aps.mit v3 vs. v2).
selection_changedReaderThe shared evaluation region (.fibps) or cycle interval (.zrw) on the file was modified after the value was extracted.
source_changedReaderThe attachment bytes changed (for example via Reupload...) after the value's analysis snapshot was saved.
file_missing / read_failedReaderThe source attachment record or its file bytes in storage could not be read; run check_storage or restore from backup.
input_changed / input_missingDerivedOne of the input values used by the formula now has a different number or was deleted.
not_fully_rerunnableDerivedAt least one input in the formula chain is Manual or Unknown, so the chain cannot be verified all the way back to raw files.
